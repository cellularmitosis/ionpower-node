# ionpower-node 0.18 — AES-CTR + HKDF

Two more crypto primitives, both with RFC-spec vectors verified.

## What's new

### AES-CTR (counter mode)

`createCipheriv` / `createDecipheriv` now accept `aes-128-ctr`,
`aes-192-ctr`, and `aes-256-ctr`. Properties:

- No padding (CTR streams over the plaintext length)
- Symmetric: encrypt == decrypt
- Parallelizable in principle (though we process serially)
- IV increments as a 128-bit big-endian counter

**NIST SP 800-38A Appendix F.5.5** (AES-256-CTR) vector passes
byte-for-byte.

```js
var c = crypto.createCipheriv('aes-256-ctr', key, iv);
c.update('non-block-aligned message');
var ct = c.final();  // same length as the input; no padding
```

### HKDF (RFC 5869)

`crypto.hkdfSync(digest, ikm, salt, info, keylen)` and the async
callback variant `crypto.hkdf(...)`.

- Extract-then-Expand key derivation
- Works over any of our hash functions (md5/sha1/sha224/sha256/sha384/sha512)
- Up to 255 × hashLen bytes of output

**RFC 5869 Test Case 1** (SHA-256, 42-byte OKM) passes byte-for-byte.

```js
var okm = crypto.hkdfSync('sha256', ikm, salt, info, 42);
```

## Install

```
tar -C /opt -xzf ionpower-node-0.18-g5-ppc.tar.gz
/opt/ionpower-node-0.18/bin/node script.js
```

## Known limitations

- **No GCM** — authenticated encryption needs GF(2¹²⁸) ghash (~100 LOC).
- **No sign/verify** — asymmetric primitives.
