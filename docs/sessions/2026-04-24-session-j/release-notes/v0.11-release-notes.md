# ionpower-node 0.11 — Promise microtask queue

Our Promises now fire through a real microtask queue, matching
Node's ordering semantics. `.then` / `.catch` / `.finally`,
`queueMicrotask`, and `process.nextTick` all defer to post-sync-code
— previously everything resolved synchronously inline.

504 libraries (unchanged). 1228 → **1231** assertions. G3 + G4
validated (see below re: G5).

## What's new

### Microtask queue

- JS-side `__microtask_queue__` array, drained by the event loop
  after every callback firing (fd watcher, timer firing, SIGCHLD
  reap).
- `_IonPromise` polyfill rewritten: resolve/reject routes callbacks
  through the queue instead of firing synchronously. `.then` on an
  already-settled Promise defers via microtask too.
- The polyfill is now installed unconditionally — SM45's native
  Promise also fires synchronously, so our polyfill shadows it for
  spec-matching ordering.
- `queueMicrotask(fn)` and `process.nextTick(fn)` push to the same
  queue.
- `main.cpp` drains microtasks after the entry script returns, then
  again after the event loop and before exit handlers.

### Ordering alignment

```
Promise.resolve(1).then(v => console.log(v));
console.log("sync");
// Before: "1" then "sync" — wrong
// After:  "sync" then "1" — matches Node
```

`setTimeout(0)` now correctly fires *after* all pending microtasks,
including ones scheduled by other microtasks.

### Test churn

Existing tests that used inline-after-.then assertions were migrated
to collect-in-closure + assert-at-exit. Covers: promise_smoke,
pinkie_smoke, p_try_smoke, p_utils_smoke, promise_utils_smoke,
p_limit_smoke, util_helpers_smoke, wave1_api_smoke, jszip_smoke.
All functionality identical; the tests now measure results after
the event loop has drained, matching typical Node-test idiom.

### Why this matters

The event loop from v0.9 and the async I/O from v0.10 are built on
callbacks, not Promises. But most modern code ergonomics are
`async/await` over Promises. Without a microtask queue, chained
`.then` callbacks fire in inverted order relative to setTimeout and
I/O callbacks. Libraries that bounce off the old behavior:
- Anything using `async function`'s desugared Promise chain
- Promise-based test runners that expect microtask-before-macrotask
- AbortController / AbortSignal integrations (future work)
- `fetch` (also future work)

Now those patterns just work.

## Install

Each tarball installs to `/opt/ionpower-node-0.11/`. Depends on a
matching `/opt/mozjs-45-ionpower*` per CPU.

```
tar -C /opt -xzf ionpower-node-0.11-g4-ppc.tar.gz
/opt/ionpower-node-0.11/bin/node script.js
```

## Known limitations (unchanged from v0.10)

- `process.nextTick` shares the same queue as microtasks (real Node
  prioritizes nextTick); no library seen relies on the distinction.
- No HTTP keep-alive / chunked-response streaming on the server.
- `https` async still falls back to curl.
- No zlib compression.
