# ionpower-node 0.44 — fs.watch flake fix + library hunt wave 13

## fs.watch smoke now reliable on Tiger

The v0.43 smoke was flaky (caught by the triad's retry-once loop):
Tiger HFS+ stores `mtime` at 1-second granularity, so the "initial"
write and the single mutate often landed in the same wall-clock
second. Only the size delta could trigger `'change'`, and the 7→17
byte gap was a tight window for the 100ms poller.

New shape: three progressive writes (7→9→13→18 bytes) over 600ms
with a 50ms poller and a 1200ms watchdog. Reliably observes 3
'change' events on G3 / G4 / G5, no retry needed.
