# ionpower-node v1.1

**Headline: Module-API surface audit + ecosystem-correct error codes.**
Eight fixes accumulated during pass 16 — five from a defensive
two-layer require-shim audit (`require.main`, `require.extensions`,
`require.resolve.paths`, `module.id`, `module.filename`), one Error
shape change that silently unblocks any library that branches on
`e.code === 'MODULE_NOT_FOUND'`, and six small fixes that unblock
the Lumo (ClojureScript REPL) bring-up on the
[lumo-darwin8-ppc](https://github.com/cellularmitosis/lumo-darwin8-ppc)
sister project. Plus a 28-package wave-3 survey covering CLI / TUI /
DB / archive categories.

## Headline fix: `require()` throws a real MODULE_NOT_FOUND Error
([`src/node_compat/require.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/src/node_compat/require.cpp))

Pre-v1.1, our `RequireNative` / `ResolveNative` threw via
`JS_ReportError`, which builds an `Error` whose `.code` is undefined.
Modern Node libraries branch on `e.code === 'MODULE_NOT_FOUND'` to
distinguish a missing optional dep from a real load-time error; the
missing code silently broke that branch — typically by mis-classifying
"feature not installed" as "feature crashed at load."

New helper `ThrowModuleNotFound` (modelled on
[`fs.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/src/node_compat/fs.cpp)'s
`ThrowFsError`) constructs a real `Error` object with
`.code = 'MODULE_NOT_FOUND'` + `.requireStack = []`. Both
`RequireNative` and `ResolveNative` route through it. While there,
`require.resolve()` was switched from a path-only stub to call
`__resolve_native__` so it also throws MODULE_NOT_FOUND on a miss,
matching Node.

The most consequential change in this release. Any package using
`try { require('optional-dep') } catch { /* ... */ }` now sees the
correct code on the catch side.

Smoke at
[`test/require_module_not_found_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/test/require_module_not_found_smoke.js)
covers relative / absolute / bare specifiers plus `require.resolve`.

## Module-API surface audit
([`src/node_compat/require.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/src/node_compat/require.cpp),
[`src/node_compat/globals.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/src/node_compat/globals.cpp))

Five Module-shaped properties that the npm ecosystem reaches for, all
landed together:

- **`require.main`** — getter on the require object, returns the
  module record for the entry script. The very first constructed
  module is stashed as `__require_main_module__` (only the first
  writer wins). A getter (rather than a plain property) is needed
  because the entry's module is stashed AFTER `__make_require__`
  returns its closure but BEFORE the wrapper runs.
- **`require.extensions`** — shared stub object with `.js` / `.json`
  / `.node` set to no-op functions. Writes accepted; custom handlers
  not honoured (Node's own ecosystem treats this as deprecated).
- **`require.resolve.paths(spec)`** — ancestor walk of
  `<dir>/node_modules`, or `null` for any builtin pre-seeded in
  `__require_cache__`. Rides for free on the existing
  `wrapped.resolve = req.resolve` because properties attached to that
  function object are visible from either side.
- **`module.id`** + **`module.filename`** — both equal the module's
  absolute path. Enriched on the module wrapper inside `LoadModuleFile`.

The shim audit was framed as preemptive, but caught a real
load-bearing failure: **bcrypt's wave-3 INSTALL_FAIL** was
`require.main is undefined` inside *npm's own* `npm-lifecycle/index.js:96`
(not bcrypt's own code). npm uses `require.main` to compute the
script working directory for lifecycle hooks. Any package with an
`install` / `preinstall` / `postinstall` script was blocked on
pre-v1.1 binaries. v1.1 clears that crash.

Smokes at
[`test/require_main_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/test/require_main_smoke.js),
[`test/require_extensions_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/test/require_extensions_smoke.js),
[`test/require_resolve_paths_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/test/require_resolve_paths_smoke.js).

The two-layer-require-shim rule that landed in v1.0 still applies and
is now flagged in source: anything added to `__make_require__` in
`require.cpp` must be forwarded by the rewrap in `globals.cpp`
(around line 10470). Inline comments at both sites warn the next
reader.

## Lumo bring-up unblocked — six small fixes
([`src/node_compat/process.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/src/node_compat/process.cpp),
[`src/node_compat/globals.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/src/node_compat/globals.cpp))

Six API-surface gaps discovered during the Lumo 1.10.1 / CLJS
1.10.520 bring-up on the sister
[lumo-darwin8-ppc](https://github.com/cellularmitosis/lumo-darwin8-ppc)
project. With these landed, a real Node-targeted ClojureScript
bundle runs on Tiger PPC.

| Fix | What |
|-----|------|
| `process.binding('util')` | Returns `{ startSigintWatchdog, stopSigintWatchdog, watchdogHasPendingSigint }` no-ops. Lumo's `cljs.js` wraps `vm.runInThisContext` with these around every form. |
| `v8.setFlagsFromString` | No-op stub. Lumo calls `--use_strict` at boot. |
| `readline.emitKeypressEvents` | No-op stub. Basic line input still works; interactive keypress decoding lost (acceptable for non-paredit use). |
| `_ReadlineInterface.prototype._setRawMode(mode)` | Delegates to `input.setRawMode` and returns previous `isRaw` (Node contract). |
| `_ReadlineInterface` auto-resume | **Real bug, not a stub.** Constructor now calls `this._input.resume()` after attaching the data listener. Pty stdin was sitting paused even with a `'data'` listener attached, so eval output never appeared during interactive REPL use. |
| `_ReadlineInterface` aliases | `this.input = this._input; this.output = this._output;` — Lumo's bundle writes to `rl.output` for redraws. |

Combined smoke at
[`test/lumo_asks_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.1/test/lumo_asks_smoke.js)
exercises all six surfaces (FakeStream tracks `resume()` calls and
`setRawMode()` invocations).

## Survey wave 3 (28 popular Node-10-era packages)

Driven by `survey-one.sh` on a real iBook G3 against the v1.0
baseline binary. Categories: CLI / TUI / DB / data / formats /
parsers / archives. **16 of 28 work clean.** Wave-3 is harder than
wave-2 by design — more bleeding-edge ESM, more native addons.

**OK (16):** commander@10, cosmiconfig, cli-table3, enquirer, mysql2,
ioredis, csv-parse, csv-stringify, xml2js, fast-xml-parser, papaparse,
bcryptjs, jsonwebtoken, extract-zip, unzipper, tar-stream.

**REQUIRE_FAIL (9):** update-notifier, boxen, chalk@5, figlet, pg,
redis@4, jose, archiver, tar — categorised in the session notes by
fix size (3 small-effort, 2 babel-fallback-investigation, 3
ecosystem-modernity, 1 stubborn-fs's own bug).

**INSTALL_FAIL (3):** knex + cheerio (`cb() never called` — npm
flake; both worth a retry), bcrypt (native addon — cleared past
`require.main is undefined` now hits child_process spawn stdio).

Full per-package logs + summary TSV under
[`docs/sessions/050-node-10-parity-pass-16/build-logs/`](https://github.com/cellularmitosis/ionpower-node/tree/v1.1/docs/sessions/050-node-10-parity-pass-16/build-logs).

## Known gaps (documented, not in scope for v1.1)

- **`Buffer.prototype.write(string, offset)`** — pg's pg-protocol
  reaches for it; ~20 lines, queued for v1.2.
- **`require('.')`** — redis@4 cluster code uses bare-dot specifier
  to mean "this directory's index.js"; resolver rejects today. ~10
  lines, queued for v1.2.
- **Built-in module property enumerability** — figlet's
  `_interopNamespaceDefault(require('path'))` iterates path keys via
  `for-in`; likely a `JSPROP_ENUMERATE` sweep across built-in
  modules. Queued.
- **Async-function parser flag in required modules** — archiver
  reports "async functions are not enabled in the parser" without
  triggering the Babel fallback. Investigation queued.
- **BigInt** (`8n`, `0n` literals) — wave-3 surfaced zero new cases.
  Still 4 known affected (superagent, make-fetch-happen, cuid2,
  ip-address). Documented for a dedicated future pass.
- **ES2018 regex** — named capture groups + lookbehind. Still just
  got@11; deferred.
- **chalk@5 / boxen** — ESM-only / `Intl.Segmenter` respectively.
  Userland workarounds: pin chalk@4. Documented.
