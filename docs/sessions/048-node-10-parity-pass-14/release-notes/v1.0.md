# ionpower-node v1.0

**Headline: the runtime hits 1.0.** The 14th Node-10 parity pass started as
"survey 30-50 more npm packages, group failures by root cause" and turned up
two latent bugs that had been quietly costing us packages whose syntax we
already support — plus the http2 stub the v0.99 handoff identified — plus
a cosmetic warning filter. After v0.99 shipped `npm install express@5 &&
node server.js` working end-to-end, this release rounds out the resolver
and parse paths so a much wider slice of the modern npm ecosystem just
works.

## Fixes

### Disable lazy parsing so the Babel fallback sees every parse error
([`src/main.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/src/main.cpp))

The require pipeline wraps each module's source in
`(function (exports, require, module, __filename, __dirname) { … })`
and `JS::Evaluate`s it. SM45's lazy parser was accepting the outer
wrapper at compile time and only diagnosing the inner body the first
time the function was called — past our parse-failure Babel fallback.
The canonical trigger: `const { a, ...rest } = opts;` (object-rest
destructuring, ES2018) inside luxon's `build/node/luxon.js`. SM45
doesn't support that syntax, but the compile succeeded; the
`invalid property id` error fired at call time when our fallback was
no longer watching.

`CompartmentOptions::setDisableLazyParsing(true)` forces eager
parsing of every function body. Small startup cost, big correctness
win: every parse error now hits the Babel fallback at the right time.

Smoke at
[`test/babel_lazy_parse_fallback_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/test/babel_lazy_parse_fallback_smoke.js).

### Resolver — try `<base>.json` for subpath imports
([`src/node_compat/require.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/src/node_compat/require.cpp))

`TryModuleExtensions` tried `<base>` / `<base>.js` / `<base>.cjs` /
`<base>/index.js` / `<base>/index.cjs` / `<base>/index.json` — but
not `<base>.json`. Node's `LOAD_AS_FILE` algorithm includes `.json`
between `.js` and `.node`. Some packages ship subpath JSON like
`spdx-license-ids/deprecated.json` and import it as
`require('spdx-license-ids/deprecated')`, which failed to resolve.
Adds the `.json` probe between `.cjs` and the package.json `main`
lookup. Unblocks `meow` end-to-end.

Smoke at
[`test/require_subpath_json_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/test/require_subpath_json_smoke.js).

### http2 throwing stub
([`src/node_compat/globals.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/src/node_compat/globals.cpp))

Several Node-10-era packages (axios@1.x, got@11) unconditionally do
`var http2 = require('http2');` at module load and only call into
http2 when an HTTP/2 request is actually issued. `require('http2')`
now returns a stub object — `connect()` / `createServer()` /
`createSecureServer()` throw with a clear pointer at the workaround
(`axios@^0.27` for HTTP/1.1-only environments); `constants` exposes
the HTTP/2 header symbols modern packages probe at load. axios@1.x
now loads and serves HTTP/1.1 traffic through its existing adapters.
`module.builtinModules` also expanded to enumerate the real
built-ins ionpower-node ships (http, https, http2, net, tls, dgram,
url, zlib).

Smoke at
[`test/http2_stub_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/test/http2_stub_smoke.js).

### Silence the SM45 `[[Prototype]]` mutation warning by default
([`src/main.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/src/main.cpp))

SM45's "mutating the [[Prototype]] of an object will cause your code
to run very slowly" warning is cosmetic for end users — common
patterns in `path-to-regexp`, `graceful-fs`, etc. trigger it at
module load with no actionable remedy. The error reporter now
filters this specific warning by default. Set
`IONPOWER_TRACE_PROTO_WARN=1` to re-enable (the same env var that
also dumps a JS stack trace at the warning site).

Defense-in-depth: the filter additionally requires
`JSREPORT_IS_WARNING(flags)` so a thrown JS `Error('[[Prototype]]')`
from user code would still surface.

Smoke at
[`test/proto_warning_filter_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.0/test/proto_warning_filter_smoke.js).

## Known gaps (documented, not in scope for v1.0)

- **BigInt** (`8n`, `0n` literals, `BigInt(…)` constructor). Modern
  packages reach for BigInt for large-integer math: cuid2, ip-address,
  some hash/crypto helpers. SM45 has no BigInt primitive; a JS-only
  polyfill is possible (jsbi-style) but would require rewriting every
  `BigInt(…)` call site. Affects `superagent` (via cuid2),
  `make-fetch-happen` (via ip-address), and likely others.
- **yargs@17** — yargs-parser throws at load when `process.version`
  is `<12`. Userland policy; not patchable from the runtime. Pin
  `yargs@^16`.
- **request-promise-native** is deprecated and its `request`
  peerDep isn't auto-installed by npm 6. Use built-in
  `https`/`http` or `fetch`.
