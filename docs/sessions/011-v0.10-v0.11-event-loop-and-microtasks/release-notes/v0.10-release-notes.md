# ionpower-node 0.10 — async I/O top to bottom

The v0.9 event loop pays back. Four additions layer on top of the
same `ioWatch` primitive and land as a cohesive release:

- **`net.Socket` + `net.createServer`** — real TCP, non-blocking
- **`http.request` / `http.createServer`** — full async HTTP/1.1
- **`fs.createReadStream` / `createWriteStream`** — file streams
- **Real `zlib` decompression** — inflate / gunzip / inflateRaw

504 libraries (unchanged). 1213 → **1228** assertions.
Triad-validated on G3 / G4 / G5.

## What's new

### net

Full TCP client + server, IPv4. Native primitives
(`__net_native__`): `socketCreate`, `bind`, `listen`, `accept`,
`connect`, `getError`, `getsockname`/`getpeername`, `shutdown`,
`closeFd`, `setNoDelay`. All non-blocking; `connect` returns
`{done, wouldBlock, errno?}` with post-`wouldBlock` completion
detected via `ioWatch(fd, WRITABLE)` + `SO_ERROR`.

JS surface:
- `net.Socket` with `.connect`, `.write`, `.end`, `.destroy`,
  events `'connect'`/`'data'`/`'end'`/`'close'`/`'error'`/`'drain'`.
  Write-queue back-pressure modeled, partial-write retry, drain on
  writable.
- `net.createServer(cb)` / `net.connect(port, host, cb)`.
- `net.isIP`/`isIPv4`/`isIPv6` helpers.

### http

In-house HTTP/1.1 parser (handles Content-Length and chunked
framing) on top of `net.Socket`:
- `http.request(opts, cb)` / `http.get(opts, cb)` — real async
  client. `ClientRequest` with `.write`/`.end`, response as
  `IncomingMessage`.
- `http.createServer(cb)` — real async server. `IncomingMessage`
  request, `ServerResponse` response (writeHead, setHeader,
  write, end).
- Sync `http.getSync`/`postSync` retained — they're still the
  HTTPS path because TLS isn't plumbed to our sockets.

### fs streams

- `fs.createReadStream(path, {highWaterMark, encoding, start, end})`
  — emits `'open'`, `'data'` chunks, `'end'`, `'close'`.
- `fs.createWriteStream(path, {flags})` — `'w'` or `'a'`; flushes
  on `.end()`; emits `'finish'`/`'close'`.
- `.pipe()` works end-to-end.

Implementation note: whole-file-in-memory (slice/trickle). Not
truly tick-by-tick disk streaming, but equivalent user API and
memory-parity with `fs.readFileSync` (which nobody complains
about).

### zlib (real inflate)

Embedded tiny-inflate (MIT, ES5, 375 LOC) as the pure-JS RFC 1951
decoder. JS wrappers add zlib-wrapping (RFC 1950) and gzip-wrapping
(RFC 1952) handling:
- `inflateRawSync(buf)` / `inflateSync(buf)` / `gunzipSync(buf)`
- `createInflate`/`createGunzip`/`createInflateRaw` — buffering
  Transforms (decompress on `.end()`).
- Async `inflate`/`gunzip` over `setImmediate`.

Compression (`gzipSync`, `deflateSync`, `createGzip`, …) still
throw a clear "not implemented" error — the retro use case is
decompression-heavy.

## Install

Each tarball installs to `/opt/ionpower-node-0.10/`.

```
tar -C /opt -xzf ionpower-node-0.10-g5-ppc.tar.gz
/opt/ionpower-node-0.10/bin/node script.js
```

## Known limitations

- No HTTP keep-alive (each request closes the socket).
- Server responses always use Content-Length, not chunked TE.
- No TLS — HTTPS async falls through to the sync curl path.
- `fs.createReadStream` loads the whole file into memory.
- No zlib compression.
