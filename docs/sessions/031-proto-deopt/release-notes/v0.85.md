Small focused release: stop the runtime from deopting itself on every `AggregateError` construction. **Also bundles the matching SpiderMonkey 45 + IonPower JIT for G3** so you can install everything in one shot, **and now ships `demos/`** under `share/ionpower-node/demos/`.

## What's new

### Fix: `_AggregateError` no longer triggers `[[Prototype]]` mutation

Our `AggregateError` polyfill was building an `Error` instance and then calling `Object.setPrototypeOf(e, _AggregateError.prototype)` to swap its prototype. SpiderMonkey 45 flags every such call with:

> mutating the `[[Prototype]]` of an object will cause your code to run very slowly; instead create the object with the correct initial `[[Prototype]]` value using `Object.create`

Each warning corresponds to a real JIT type-info invalidation. Rewrote the constructor to set the prototype chain correctly at construction time via the standard `if (!(this instanceof X)) return new X(...)` factory pattern. `instanceof Error` and `instanceof AggregateError` both still work; no `setPrototypeOf` call.

### Diagnostic: `IONPOWER_TRACE_PROTO_WARN`

`src/main.cpp`'s error reporter now optionally dumps a JS stack alongside any `[[Prototype]]` warning. Off by default (one `getenv` + one `strstr` per warning, both cheap). Set `IONPOWER_TRACE_PROTO_WARN=1` to see exactly which call site triggered each warning. Useful for the next round of perf-deopt hunting.

### Demos shipped in the install

The install rule now copies `demos/` to `share/ionpower-node/demos/` along with the closure of `test/vendor/*` files the demos require at runtime (express + its bundled `node_modules/<x>/index.js` shim targets, the standalone vendor files used as direct requires, and xml2js/xmlbuilder/sax). Adds ~1.3 MB compressed. Gives anyone unpacking the tarball a runnable starting point without needing a checkout of the source tree.

The two chat demos (`demos/chat/` and `demos/express-chat/`) work out of the box on **modern browsers AND Safari 4 on Tiger PPC** — the same machine running the server can also be the client. Tiger Safari has no `WebSocket` / `fetch` / CSS variables / modern flexbox, so the page does feature-detection and falls back to XHR short-poll plus a CSS-2.1 absolute-positioning layout. Modern browsers keep using WS push and don't notice.

## What we left alone

`make test-all` still emits 33 `[[Prototype]]` warnings, **all 33 from third-party vendored libraries** — the TypeScript-compiled `__extends` template (the biggest single source), Babel internals, regenerator runtime, and a handful of ad-hoc `Object.setPrototypeOf` uses inside specific libs. Each fires once during library load, not in steady-state hot paths, so the steady-state perf cost is bounded.

Patching every vendored lib to remove these would be brittle (vendored libs get re-fetched on update) and high-effort for minimal payoff. We accept them as the cost of running real-world JS libraries on SM45. Full disposition list with stack traces in [`docs/sessions/2026-04-30-session-3-proto-deopt/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.85/docs/sessions/2026-04-30-session-3-proto-deopt/notes.md).

## Tarballs (G3 only this release)

This release ships G3 artifacts only; the G3 binary runs unchanged on G4 and G5 (G3 instructions are a strict subset of G4/G5), so a G4 or G5 host can install the G3 tarball for the runtime + demos. AltiVec-tuned G4 and G5 builds will return in the next release.

| Arch | Runtime | SpiderMonkey 45 + IonPower |
|---|---|---|
| G3 | `ionpower-node-0.85-g3-ppc.tar.gz` | `mozjs-45-ionpower-g3.tar.gz` |

The mozjs tarball is the static archives + headers + `js` shell + `js-config`, built from the [TenFourFox SM45 + IonPower tree](https://github.com/classilla/tenfourfox) with `-mcpu=750 -mtune=750`. Unpacks to `/opt/mozjs-45-ionpower-g3/` (~220 MB installed, ~62 MB compressed). Same layout the build host uses; same headers a downstream embedder would need.

## Try it out

On any G3, G4, or G5 Mac running Tiger or Leopard:

```
sudo mkdir -p /opt
sudo chmod ugo+rwx /opt
cd /opt
curl http://leopard.sh/binpkgs/gcc-libs-4.9.4.tiger.g3.tar.gz | gunzip | tar x
ln -s gcc-libs-4.9.4 gcc-4.9.4
curl http://leopard.sh/dist/ca-certificates-20230110.tar.gz | gunzip | tar x
curl http://leopard.sh/misc/beta/mozjs-45-ionpower-g3.tar.gz | gunzip | tar x
curl http://leopard.sh/misc/beta/ionpower-node-0.85-g3-ppc.tar.gz | gunzip | tar x
cd /opt/ionpower-node-0.85/bin
./node ../share/ionpower-node/demos/express-chat/server.js
```

Then point any browser on the LAN at `http://<host>:8080/` — including Tiger Safari on the host itself.

The two tarballs above are also attached to this release directly (`mozjs-45-ionpower-g3.tar.gz` and `ionpower-node-0.85-g3-ppc.tar.gz`); the `leopard.sh` URLs are mirrors that pair the runtime with the gcc-4.9.4 runtime libs and CA bundle that the binary needs.

OpenSSL 1.1.1t is statically linked into the runtime — no separate install needed for `tls`/`https`/`crypto`.
