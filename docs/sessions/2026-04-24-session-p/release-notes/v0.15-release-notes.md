# ionpower-node 0.15 — library hunt wave 2

Another hunt wave. Targeting libraries from the auth / crypto /
data-integrity / type-predicate ecosystems.

**560 → 575+ libraries**. Assertions **1330 → 1345+**.

## What's new

### batch_wave_n_smoke (fresh from npm, 10 libs pass)

Auth, crypto, data-integrity:
- **accept-language-parser** — RFC 7231 Accept-Language parser
- **base64-js** v1 — typed-array base64 encoder/decoder
- **cookiejar** — full cookie jar (not just parser)
- **fast-deep-equal** — recursive equality
- **json-schema-traverse** — walk a JSON schema tree
- **random-bytes** — `random-bytes.sync(16)` wrapper
- **uid-safe** — URL-safe random IDs
- **uri-js** v4 — full URI parser (superset of `new URL`)
- **hasha** — thin wrapper over Node's crypto
- **nanoid** v3 — 21-char URL-safe IDs

Skipped with clear messages (missing sibling modules): crypto-random-string,
is-arguments, short-uuid, verror, csrf.

### batch_wave_n2_smoke (es-shims — 2 pass)

Most es-shims packages depend heavily on each other (call-bind,
get-intrinsic, has-tostringtag, etc.), making them hard to vendor
for our flat layout.

- **functions-have-names**
- **has-proto**

Skipped (sibling deps): is-date-object, is-regex, object-is,
es-define-property.

## Running totals

- Libraries: 504 (v0.12) → 560 (v0.13) → 575+ (v0.15)
- Assertions: 1255 → 1317 → 1345+

## Not done

- es-shims bundle (call-bind, get-intrinsic, etc.) — would unlock
  many polyfill libraries. Needs vendor-tree flattening or a shim
  resolver.
- Heavy consumers (formidable, jsonwebtoken, busboy, form-data) —
  dense dep graphs; deferred to a dedicated multi-sibling batch.
