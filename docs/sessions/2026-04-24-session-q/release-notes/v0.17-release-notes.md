# ionpower-node 0.17 — AES-CBC

`crypto.createCipheriv` / `createDecipheriv` for **AES-128/192/256-CBC**.
Pure JS, FIPS 197 compliant, with PKCS#7 padding (auto-enabled, opt-out
via `.setAutoPadding(false)`).

**NIST SP 800-38A Appendix F.2.5** (AES-256-CBC) test vector passes
byte-for-byte.

## What's new

- Full AES state machine: S-box + InvS-box + key expansion for
  128/192/256-bit keys + encrypt/decrypt block
- GF(2⁸) math: MixColumns via xtime, InvMixColumns with Me/Mb/Md/M9
  multiplicands
- CBC mode: IV-chained encrypt/decrypt
- PKCS#7 padding: auto-pad/unpad by default, defeatable

```js
var crypto = require('crypto');
var key = crypto.randomBytes(32);
var iv  = crypto.randomBytes(16);
var c = crypto.createCipheriv('aes-256-cbc', key, iv);
c.update('my secret payload');
var ciphertext = c.final();
```

## Install

```
tar -C /opt -xzf ionpower-node-0.17-g5-ppc.tar.gz
/opt/ionpower-node-0.17/bin/node script.js
```

## Known limitations

- **CBC only** — no GCM / CTR / ECB yet.
- **No authenticated encryption**. GCM would need GF(2¹²⁸) ghash
  (~100 more LOC).
- **Pure JS** — slower than OpenSSL. Fine for typical use
  (session-cookie encryption, small payloads); bulk encryption would
  benefit from a future native binding.
