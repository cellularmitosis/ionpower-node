Driven by the lumo-darwin8-ppc Path B bring-up — three small surface-area additions that came out of running self-hosted ClojureScript on the v0.85 runtime. None block lumo today, but each removes a paper cut for downstream packages that reach for these Node modules.

## What's new

### `require('repl')` stub

Lumo and a handful of REPL-aware libraries reference `require('repl')` at module-load time even when they only use it on a fallback path. Before v0.86 the `require()` call threw `Cannot find module 'repl'` and short-circuited the whole loader. Now `require('repl')` returns `{ start, REPLServer, Recoverable }` — `start()` throws `Error('repl not implemented')` if anyone actually calls it (we have no readline-driven REPL), but feature-detecting consumers see the surface and proceed.

Smoke: [`test/repl_stub_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.86/test/repl_stub_smoke.js).

### `require('v8')` stub

Same trigger as `repl` — lumo (and others) reach for `v8.serialize` / `v8.deserialize` as a fast analyzer-cache codec, and `v8.getHeapStatistics` for diagnostics. Now seeded into the require cache: `serialize` / `deserialize` round-trip via JSON (lossy for non-JSON values, but that covers the realistic cache-content case), `getHeapStatistics` returns an empty object.

Smoke: [`test/v8_stub_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.86/test/v8_stub_smoke.js).

### Babel: explicit `transform-logical-assignment-operators`

The Babel-on-parse-failure fallback now passes `plugins: ['transform-logical-assignment-operators']` alongside the existing `preset-env` (`targets: { ie: '11' }`) call. ES2021 logical-assignment operators (`||=`, `&&=`, `??=`) lower correctly when a `require()`d file contains them — relevant for ClojureScript `:advanced` output which occasionally emits a single one of these in Closure Library code.

Smoke: [`test/babel_logical_assignment_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.86/test/babel_logical_assignment_smoke.js) covers the ||= / &&= / ??= matrix end-to-end through `require()`.

`module.builtinModules` and `module.isBuiltin('repl')` / `('v8')` updated accordingly.

## What we didn't do

Real `vm.runInNewContext` compartment isolation is still on the docket — see [`docs/sessions/2026-05-09-session-1-handoff-from-lumo/followups.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.86/docs/sessions/2026-05-09-session-1-handoff-from-lumo/followups.md). The current JS shim is enough for production-build Lumo (`runInThisContext`); a real native `createContext` is wanted for dev-build Lumo and for future libraries that exercise sandbox isolation. ~one day of native work, deferred.

The eval-path Babel fallback is also captured in the same followups doc — today, only `require()` falls back to Babel on SyntaxError; `(0, eval)(...)` and `vm.runInThisContext(code)` do not.

## Try it out

```
sudo mkdir -p /opt
sudo chmod ugo+rwx /opt
cd /opt
curl http://leopard.sh/binpkgs/gcc-libs-4.9.4.tiger.g3.tar.gz | gunzip | tar x
ln -s gcc-libs-4.9.4 gcc-4.9.4
curl http://leopard.sh/dist/ca-certificates-20230110.tar.gz | gunzip | tar x
curl http://leopard.sh/misc/beta/mozjs-45-ionpower-g3.tar.gz | gunzip | tar x
curl http://leopard.sh/misc/beta/ionpower-node-0.86-g3-ppc.tar.gz | gunzip | tar x
cd /opt/ionpower-node-0.86/bin
./node ../share/ionpower-node/demos/express-chat/server.js
```

Then point any browser on the LAN at `http://<host>:8080/` — including Tiger Safari on the host itself.

OpenSSL 1.1.1t is statically linked into the runtime — no separate install needed for `tls`/`https`/`crypto`.
