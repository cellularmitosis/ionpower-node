v0.14: zlib compression (stored mode)

Session N. Completes the zlib story — v0.10 shipped inflate, v0.14
ships deflate. Compression is "stored" mode only (RFC 1951 BTYPE=00):
no compression ratio, but valid deflate frames that any conforming
decoder (gunzip(1), Node's native zlib, pako) consumes.

- _deflateRaw_stored: splits input into ≤65535-byte blocks, emits
  5-byte BFINAL+BTYPE=00+LEN+NLEN header per block.
- _adler32: RFC 1950 checksum with 5552-byte chunking.
- _crc32: precomputed 256-entry table; RFC 1952 gzip.
- zlib.gzipSync / deflateSync / deflateRawSync — sync.
- zlib.gzip / deflate / ... — async via setImmediate.
- zlib.createGzip / createDeflate / createDeflateRaw — Transforms
  (buffer + emit on .end()).

Round-trip verified: our output → our inflate, our gzip → real
gunzip(1) on PPC Tiger. Multi-block (>64KB), empty input both OK.

Library count unchanged (560+). Assertions 1317 → ~1330.
