Driven by the npm 6.14.18 bring-up experiment captured in
[`docs/sessions/2026-05-09-session-2-npm-6-bootstrap/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/docs/sessions/2026-05-09-session-2-npm-6-bootstrap/notes.md)
— a first wave of small runtime additions that close the gaps real-world
npm hit when running on v0.86. Project framing also changed: ionpower-node
now formally targets **Node 10.24.1** as its parity yardstick (see
[`docs/plans/node-target-version.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/docs/plans/node-target-version.md)).

## What's new

### `process.version` policy: `v10.24.1`

`process.version` previously reported `'ionpower-node-0.86'` — a
deliberate "we are not Node" identifier. The cost showed up in the npm
6.14.18 bring-up: npm fed the value into a real semver parser
(`semver.satisfies(process.version, '>=6 <11')`) and threw
`Invalid Version: ionpower` on the spot.

Going forward, `process.version` reports `'v10.24.1'` (the last release
of the Node 10 line). The runtime's own identity moves to
`process.versions['ionpower-node']`, which carries `'0.87'`. This is the
project's measurable parity target now: get to where Node-10-shaped code
runs cleanly on us, then bump the target to Node 12.

### `process.versions['ionpower-node']` (dashed) + cleaner shape

`process.versions` is now `{ node: '10.24.1', 'ionpower-node': '0.87',
spidermonkey: '45', openssl: <real>, v8: '8.4.0' }`. The dashed
`'ionpower-node'` key needs bracket access; the previous undashed
`ionpower` key is gone.

Smoke: [`test/process_version_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/process_version_smoke.js).

### `process.execPath`

Now reports the absolute path to the runtime binary (mirrors
`process.argv[0]`). Real Node has this; libraries like `which` and
`isexe` use it for self-detection. Was `undefined` pre-v0.87.

### `process.binding(name)` empty-object stub

Legacy private API older libraries (fs-minipass, npm internals) reach
into for native C++ bindings. Returns `{}` — module load succeeds; if
anything actually CALLS a binding method later, it fails at use-time
with `not a function`, which is the right behavior. We deliberately do
NOT expose internals.

Smoke: [`test/process_extras_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/process_extras_smoke.js).

### `require('constants')`

Real seed (was missing). Exposes `O_RDONLY`/`O_WRONLY`/`O_RDWR`/
`O_CREAT`/`O_TRUNC`/`O_APPEND`/`O_EXCL`/`O_NOFOLLOW`/`O_SYMLINK`/etc;
`S_IFMT`/`S_IFREG`/`S_IFDIR`/`S_IFLNK`/`S_IFSOCK`/`S_IFCHR`/`S_IFBLK`/
`S_IFIFO`; permission bits (`S_IRUSR`/`S_IWUSR`/.../`S_IXOTH`); and
common errno integers (darwin numbers — `EPERM=1`, `ENOENT=2`, ...,
`EILSEQ=92`). graceful-fs and similar libraries probe via
`hasOwnProperty('O_SYMLINK')` for feature detection.

`'constants'` added to `module.builtinModules`. Signal numbers punted
to a later pass.

Smoke: [`test/constants_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/constants_smoke.js).

### `require()` resolves `<dir>/index.json`

Real Node tries `<base>/index.{js,json,node}` after `package.json`
"main". Pre-v0.87 we missed the `.json` case, so packages shaped like
`spdx-license-ids` (which ship only an `index.json` and no `"main"`)
failed to resolve. Now wired into `TryModuleExtensions` after
`index.cjs`.

Smoke: [`test/index_json_resolve_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/index_json_resolve_smoke.js).

### `fs.readlink` / `fs.readlinkSync`

Real `readlink(2)`-backed implementation. Pre-v0.87 we only had
`fs.lstat` (and even that aliased to `stat`); anything that promisified
`fs.readlink` (e.g. read-package-tree) blew up.

Smoke: [`test/fs_readlink_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/fs_readlink_smoke.js).

### `fs.{truncate,symlink,chown,utimes,fchmod}` (sync + async)

Each one syscall, sync + async via the existing `_fsAsync` helper, plus
`fs.promises.*` wrappers. `fs.appendFile` was already present in v0.86.

Also: `fs.lchown(Sync) = fs.chown(Sync)` alias for now (matches the
existing `lstat = stat` approximation; a real symlink-aware variant
will come in a later pass when a consumer specifically needs it).

Smoke: [`test/fs_extras2_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/fs_extras2_smoke.js).

### `Module._nodeModulePaths(from)`

Bonus addition driven by the install-pipeline experiment: resolve-from
(reached by `lib/install.js`) calls
`require('module')._nodeModulePaths(fromDir)` to discover node_modules
locations. Implemented as a POSIX ancestor walk (`<from>/node_modules`,
`<from>/../node_modules`, … `/node_modules`).

Smoke: [`test/module_node_paths_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/test/module_node_paths_smoke.js).

## npm 6.14.18 install pipeline status

After the v0.87 surface lands, `npm install mri` on ionpower-node
gets *much* further than v0.86 — npm now loads cleanly, runs the
config chain past `which`/`isexe`, gets into `lib/install.js`, and
reaches deep into `lib/utils/lifecycle.js → npm-lifecycle → resolve-from`
before hitting the next plateau:
**`Module._resolveFilename is not a function`**.

`Module._resolveFilename` is the canonical "resolve-only, don't load"
entry on the Module class. We have a working C++ resolver but no
JS-exposed resolve-only entry yet. That, plus a likely cascade in
`mkdirp → graceful-fs → glob`, is the pass-2 work — see
[`docs/sessions/2026-05-10-session-1-node-10-parity-pass-1/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.87/docs/sessions/2026-05-10-session-1-node-10-parity-pass-1/notes.md).

**`npm install mri` is NOT end-to-end yet.** v0.87 closes the wave-1
gaps that blocked npm from leaving its own bootstrap; pass-2 closes
the install-pipeline gaps that block it from actually writing
`node_modules/`.

## What we didn't do

- **`process.binding('fs').writeBuffers` etc.** — module load
  succeeds, but if anything actually CALLS a bound method, it'll fail
  at use-time. Real implementations of `writeBuffers` /
  `FSReqWrap` are out of scope.
- **A `require('os').constants` proper namespace.** Today
  `require('constants')` is the seed; the parallel `os.constants` tree
  is a Node-12-era refinement and waits for the Node 12 jump.
- **Recursive dep installation via `npm install`.** Pass-1 closes
  enough gaps for a single-package install (mri has zero deps); a
  package with transitive deps will surface install-pipeline gaps not
  yet captured.
- **Signal numbers in `constants`.** Plenty of Node-internal code
  references `SIGTERM`/etc. Until a real consumer asks, the fs subset
  is what shipped.

## Try it out

```
sudo mkdir -p /opt
sudo chmod ugo+rwx /opt
cd /opt
curl http://leopard.sh/binpkgs/gcc-libs-4.9.4.tiger.g3.tar.gz | gunzip | tar x
ln -s gcc-libs-4.9.4 gcc-4.9.4
curl http://leopard.sh/dist/ca-certificates-20230110.tar.gz | gunzip | tar x
curl http://leopard.sh/misc/beta/mozjs-45-ionpower-g3.tar.gz | gunzip | tar x
curl http://leopard.sh/misc/beta/ionpower-node-0.87-g3-ppc.tar.gz | gunzip | tar x
cd /opt/ionpower-node-0.87/bin
./node ../share/ionpower-node/demos/express-chat/server.js
```

Then point any browser on the LAN at `http://<host>:8080/` — including
Tiger Safari on the host itself.

OpenSSL 1.1.1t is statically linked into the runtime — no separate
install needed for `tls`/`https`/`crypto`.
