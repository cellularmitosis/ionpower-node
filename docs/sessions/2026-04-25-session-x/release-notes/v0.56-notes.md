# ionpower-node 0.56 — `async` / `await` / `for await`

These were almost free — the lowering path was already in place
(it's how ESM modules already work), just one polyfill missing.

## What's working

```js
async function fetchAndAdd() {
    const a = await Promise.resolve(1);
    const b = await Promise.resolve(2);
    return a + b;
}

await fetchAndAdd();   // 3

try {
    await Promise.reject(new Error("nope"));
} catch (e) {
    // caught
}

// for-await over events.on(...)
for await (const args of events.on(emitter, "data")) {
    if (done) break;
}

// for-await over a WHATWG ReadableStream
for await (const chunk of readableStream) {
    process(chunk);
}
```

## How

SM45's parser rejects `async`/`await` syntax. Our `require.cpp`
catches the parse failure, runs the source through `@babel/standalone`
(lazy-loaded — same path that handles ESM `import`/`export`), and
re-evaluates the lowered ES5. Babel transforms async functions into
generator-based state machines that chain through `Promise.then`.
Our `_IonPromise` routes those `.then`s through the microtask queue,
so the lowered code runs correctly.

## What v0.56 adds

1. **`Symbol.asyncIterator` polyfill.** SM45 ships `Symbol` but no
   `asyncIterator` well-known. Babel's lowered `for await` runtime
   helper checks for it. Polyfilled in bootstrap as a fresh `Symbol(...)`.

2. **WebStreams Reader `.next()` adapter** — async iterator protocol
   expects `.next()` returning `Promise<{value, done}>`; our Reader
   has `.read()` with that exact shape.

3. **`[Symbol.asyncIterator]`** pinned on:
   - `_ReadableStreamDefaultReader.prototype` (returns self)
   - `_ReadableStream.prototype` (returns `this.getReader()`)
   - `events.on()` iterators (via v0.48's already-conditional code,
     now reaching the assignment)
