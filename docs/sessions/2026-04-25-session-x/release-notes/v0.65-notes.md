# ionpower-node 0.65 — RSA via vendored node-forge

**First RSA support.** Uses node-forge (vendored at
`test/vendor/node-forge/`, installed under
`share/ionpower-node/vendor/node-forge/`) for the heavy bignum
+ sign/verify pure-JS implementation.

## What's new

```js
const crypto = require('crypto');

const { publicKey, privateKey } = crypto.generateKeyPairSync('rsa', {
    modulusLength: 1024,
    publicExponent: 0x10001
});

const sig = crypto.sign('sha256', Buffer.from('hi'), privateKey);
crypto.verify('sha256', Buffer.from('hi'), publicKey, sig);   // true

privateKey.export({ format: 'pem' });   // RSA PRIVATE KEY block
privateKey.export({ format: 'der' });   // raw bytes Buffer
```

## Performance (1024-bit keygen, real hardware)

| Host | Time |
|---|---|
| G5 (1.6 GHz) | ~4.2 s |
| G4 (1.42 GHz) | ~5.2 s |
| G3 (700 MHz)  | ~10.6 s |

Sign/verify is single-digit ms. Don't use this in latency-sensitive
paths; do use it for one-off cert generation, per-deployment key
creation, or signature verification of stored data.

## Mechanics

- node-forge is lazy-loaded (separate from tweetnacl path) so its
  ~31k lines of pure JS don't load unless RSA is actually used.
- forge's `pki.rsa.generateKeyPair` tries to call Node's native
  `crypto.generateKeyPairSync` first as an optimisation. We delegate
  back to forge — which would recurse — so we set
  `crypto.__ionpower_inhibit_rsa = true` while forge runs, and
  patched forge's `rsa.js` to (a) honour that flag and (b) wrap the
  native call in `try/catch` so it falls through to its pure-JS path
  if the host's shim throws.
- KeyObject wrapper carries the forge key on `_forge` plus an
  `.export({ format: 'pem' | 'der' })` method.
- `sha256` / `sha384` / `sha512` algorithms supported for sign/verify.

## Verified

6 assertions on G3 / G4 / G5:
- `crypto.generateKeyPairSync('rsa', { modulusLength: 1024 })`
- `crypto.sign('sha256', msg, privateKey)` returns 128-byte sig
- `crypto.verify('sha256', msg, publicKey, sig)` is true
- Bit-flipped sig rejected; wrong message rejected
- PEM export contains `BEGIN [RSA] PRIVATE KEY` / `BEGIN PUBLIC KEY`
- DER export is non-trivial Buffer

## Still missing

- ECDSA (NIST curves)
- Classic ECDH (NIST curves)
- RSA-OAEP encrypt/decrypt (forge supports it, just not wired yet)
