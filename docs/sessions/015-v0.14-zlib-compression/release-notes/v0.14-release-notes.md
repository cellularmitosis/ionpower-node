# ionpower-node 0.14 — zlib compression

v0.10 shipped real `zlib` *de*compression via embedded tiny-inflate.
v0.14 adds the other half: compression, in RFC 1951 "stored" mode
(uncompressed blocks with valid deflate framing).

**Ratio:** 1:1 — no compression gain. **Correctness:** full.
Output is valid deflate that any RFC-conforming decoder — including
`gunzip(1)`, Node's native zlib, pako, etc — consumes cleanly.

## What's new

### Real compression (stored mode)

- `zlib.gzipSync(data)` — RFC 1952 gzip format: magic `1f 8b` + CM=8 +
  FLG=0 + stored-mode deflate + CRC-32 trailer + ISIZE trailer.
- `zlib.deflateSync(data)` — RFC 1950 zlib format: CMF/FLG header +
  stored-mode deflate + Adler-32 trailer.
- `zlib.deflateRawSync(data)` — raw RFC 1951 stored blocks.
- Async variants: `zlib.gzip/gunzip/deflate/inflate(buf, opts, cb)`.
- Transform variants: `zlib.createGzip`, `createDeflate`,
  `createDeflateRaw` — buffer all writes, emit compressed output on
  `.end()`. Symmetric with `createGunzip`/`createInflate`/`createInflateRaw`.

### Round-trip verified

- **Our deflate → our inflate**: all three formats round-trip correctly
  for small inputs, multi-block inputs (>64KB), and empty input.
- **Our gzip → real `gunzip(1)`** on PowerPC Tiger decodes back to the
  original text.

### Why stored mode?

Real deflate compression (LZ77 + Huffman) is ~600 more lines of
careful code. "Stored" mode is 40 lines, correct, and unblocks every
library that wants to *produce* valid deflate output:

- HTTP server handlers emitting `Content-Encoding: gzip`
- tar/tar.gz writers
- `.zip` creators
- log compressors

Consumers that need actual size reduction (network bandwidth, disk
space) still want a real encoder. That's the v0.15+ job if someone
hits it.

### Runtime bookkeeping

New helpers (pure JS, embedded in the bootstrap):
- `_adler32(bytes)` — RFC 1950 Adler-32 with 5552-byte chunking for
  32-bit safety.
- `_crc32(bytes)` — precomputed 256-entry table; RFC 1952 gzip CRC.
- `_deflateRaw_stored(bytes)` — splits input into ≤65535-byte blocks,
  emits 5-byte header (BFINAL + BTYPE=00 + LEN + NLEN) per block.

## Install

Each tarball installs to `/opt/ionpower-node-0.14/`.

```
tar -C /opt -xzf ionpower-node-0.14-g5-ppc.tar.gz
/opt/ionpower-node-0.14/bin/node script.js
```

## Known limitations

- **No compression ratio**: stored mode = 1:1 (actually +5 bytes per
  64K block). Fine for correctness-sensitive users; not for those
  needing real size savings.
- **No brotli**: `createBrotliCompress` still throws.
- HTTPS through `fetch` still uses the sync curl shim.
