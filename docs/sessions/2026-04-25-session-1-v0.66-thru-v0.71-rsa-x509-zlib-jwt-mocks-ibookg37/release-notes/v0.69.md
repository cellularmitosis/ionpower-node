## What's new

### module.Module class

`require('module')` now exposes a Node-shape `Module` constructor, with
the bits libraries reach for when they want to walk the require system:

```js
var Module = require('module').Module;

new Module(id, parent);          // proper module-shape object
Module._cache;                   // === __require_cache__
Module._extensions;              // { '.js', '.json', '.cjs' } stubs
Module.wrap(source);             // -> '(function (exports, require, module, __filename, __dirname) { ' + src + '\n});'
Module.wrapper;                  // [prefix, suffix] for libraries that splice manually
Module.builtinModules;
Module.isBuiltin('node:fs');
Module.createRequire(filename);  // already worked at module-level; now also static-method
```

The `module` README row goes from "Missing" to working.

### JWT RS256 / EdDSA validation

`test/jwt_rs256_smoke.js` exercises the asymmetric crypto stack
delivered in v0.65-v0.67 (RSA via node-forge, Ed25519 via tweetnacl,
PEM key import) against real-world JWT use cases — manually constructing
+ verifying tokens (no JWT library, just the runtime's `crypto`):

- **RS256** with `crypto.generateKeyPairSync('rsa')` keys
- **RS256** with PEM-exported then re-imported `KeyObject`s
- RS256 tamper rejection
- **EdDSA** (Ed25519) sign / verify / tamper
- **HS256** (HMAC-SHA256) symmetric reference
- Cross-algorithm rejection (RS256 token does not verify against EdDSA key)

This proves a runtime-native JWT implementation works end-to-end on
PowerPC Tiger.
