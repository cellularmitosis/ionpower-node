# ionpower-node 0.20 — `crypto.subtle` (WebCrypto)

The Node `crypto` module is nice. `crypto.subtle` is what modern
JS expects — Promise-based, ArrayBuffer-in/ArrayBuffer-out, and
portable across Node / browsers / Deno / Bun.

This release wraps our existing symmetric primitives in the WHATWG
SubtleCrypto shape.

## What's new

### `globalThis.crypto.subtle.*`

All the core operations — Promise-based, ArrayBuffer-in:

- **`digest(algorithm, data)`** — `SHA-1` / `SHA-256` / `SHA-384` /
  `SHA-512`
- **`importKey(format, keyData, algorithm, extractable, usages)`** —
  `"raw"` format only
- **`exportKey(format, key)`** — `"raw"` format; respects `extractable`
- **`generateKey(algorithm, extractable, usages)`** — HMAC, AES-CBC/CTR/GCM
- **`sign` / `verify`** — HMAC (SHA-1/256/384/512)
- **`encrypt` / `decrypt`** — AES-CBC / AES-CTR / AES-GCM. GCM tag
  is appended/extracted from the ciphertext per WebCrypto convention.
- **`deriveBits`** — PBKDF2 (over any supported hash) + HKDF

### Example

```js
const pt = new TextEncoder().encode('sensitive payload');
const key = await crypto.subtle.generateKey(
    { name: 'AES-GCM', length: 256 }, true, ['encrypt','decrypt']);
const iv = crypto.getRandomValues(new Uint8Array(12));
const ct = await crypto.subtle.encrypt(
    { name: 'AES-GCM', iv }, key, pt);
const recovered = await crypto.subtle.decrypt(
    { name: 'AES-GCM', iv }, key, ct);
console.log(new TextDecoder().decode(recovered));  // 'sensitive payload'
```

### Not in this release

- **No asymmetric**: `RSA-OAEP`, `RSA-PSS`, `ECDSA`, `ECDH`,
  `Ed25519` — all absent. These would need a bignum library +
  elliptic curve math; substantial work.
- **No JWK format**: `importKey('jwk', ...)` throws. We support `'raw'`
  only. Could be added if a library bounces.
- **No `AES-KW`** (key wrapping).

With this, `crypto.*` is ✅ in the API table for both the Node-style
and WebCrypto surfaces (symmetric + hashing + KDF).
