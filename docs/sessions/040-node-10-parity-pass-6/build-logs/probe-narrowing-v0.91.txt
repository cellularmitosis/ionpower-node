3) FAIL: Promise.then(res => res.on('data', ...))

   probe-prom-https.js: wrap https.get in new Promise(resolve =>
   https.get(url, resolve)), then in .then attach data/end handlers:

     START
     response cb fired STATUS 200 +449ms
     THEN fired +501ms
     WD 25s
     exit=7

   The response callback fires synchronously inside the http parser.
   The Promise's .then runs as a microtask after the parser's
   sync feedBody(leftover) has already emit'd 'data' to no listeners.
   Listeners attach a microtask too late; data is lost.

----------------------------------------------------------------------
6) VALIDATION: monkey-patch IM.prototype to buffer

   probe-with-patch.js: same Promise + late-attach pattern, but
   first patches http.IncomingMessage.prototype to buffer 'data'/
   'end' until a 'data' listener attaches:

     PATCH installed; START
     THEN +513ms STATUS=200 enc=gzip
     END len=3168 +518ms
     exit=0

   With patch loaded: the late-attached data listener sees the
   buffered chunk; end fires; promise chain proceeds cleanly.

----------------------------------------------------------------------
Root cause: _IncomingMessage in src/node_compat/globals.cpp emits
'data' eagerly via response.emit('data', d) without buffering;
pause/resume are no-ops. When user code attaches the data listener
even one microtask after the response callback (the universal
Promise pattern in pacote / node-fetch / make-fetch-happen), the
sync feedBody(leftover) has already emit'd the body to a listener-
less stream and the bytes are dropped.

Fix: implement the standard Readable paused/flowing semantics on
_IncomingMessage — buffer in paused mode, drain on data-listener
attach via newListener hook + process.nextTick.

Same shape as the pass-5 TLS BIO retry-on-stall fix: a JS-only edit
inside the bundled bootstrap in src/node_compat/globals.cpp.
