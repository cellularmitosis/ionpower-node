v0.92 lands three foundational fixes that pass-5's TLS-to-Cloudflare
work needed to actually be useful for modern fetch / Promise-based
HTTP consumers: the IncomingMessage paused/flowing semantics, the
gunzip stream's buffer-until-listener-attaches contract, and a
real `instanceof Stream` shape for `process.stdout` / `process.stderr`.
Plus the small carryovers from pass-5's plan
(`process.getuid` family, `fs` error shape, a less-flaky TLS smoke).

Driven by [`docs/sessions/2026-05-11-session-2-node-10-parity-pass-6/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.92/docs/sessions/2026-05-11-session-2-node-10-parity-pass-6/notes.md).

## Summary

Three interlocking stream-contract bugs were silently swallowing the
HTTP response body whenever a consumer attached its `data` listener
even one microtask after the response callback fired. Pass-5 closed
the TLS BIO stall so the wire delivered the body; v0.92 makes sure
the JS side delivers it to the consumer.

- **IncomingMessage**: bytes emitted by `_ClientRequest`'s sync
  `feedBody(leftover)` (right after the `'response'` event) used to
  hit a listener-less stream and vanish. Now they buffer in
  paused mode and drain on first `data`-listener attach via
  `process.nextTick` — Node Readable semantics.
- **`zlib.createGunzip()`**: same shape, one layer down. `end()`
  was firing `setImmediate(() => emit('data', decoded))`. If user
  code (pacote / node-fetch / make-fetch-happen) attached the
  data listener on the gunzip stream via a Promise microtask, the
  setImmediate fired first and the decoded blob was dropped.
  Same buffer-and-drain fix; applied to the compress side
  (`_mkDeflateTransform`) for symmetry.
- **`process.stdout` / `process.stderr` not `instanceof Stream`**:
  C++ exposes them as plain Objects. npm 6's config validator
  rejects them and falls back to `undefined`. `Gauge.setWriteTo(undefined)`
  then throws TypeError inside a timer callback, and `npm.load`'s
  completion callback never fires. Wrapped both stdio streams in
  `_Writable` instances at JS bootstrap; `_write` delegates to the
  original native `write` so syscall behaviour is unchanged.

Tests: 470 (v0.91) → 472 (v0.92, +2 new). G3 + G4 + G5 triad-
builds clean.

## What's new (pass 6)

### `_IncomingMessage` paused/flowing semantics

`src/node_compat/globals.cpp`:
- Constructor inits `_imBuf` / `_imFlowing` / `_imEndQueued`.
- `emit()` override buffers `'data'` / `'end'` when not flowing.
- `on()` override sets flowing on first `'data'` listener attach
  and schedules a drain via `process.nextTick`.
- `.pause()` / `.resume()` actually work (used to be no-ops).
- `.pipe(dest)` attaches `'end'` before `'data'` so the inline
  drain doesn't fire `'end'` before pipe's end-forwarder.

Smoke: [`test/http_paused_data_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.92/test/http_paused_data_smoke.js)
— local http server; fetches via
`new Promise(resolve => http.get(url, resolve)).then(res => res.on('data', ...))`;
asserts the body lands. Two variants (plain `.then` attach;
`.then` + explicit `.resume()`). Network-free; deterministic
regression guard.

### `zlib.createGunzip()` buffer-until-listener-attaches

`_mkInflateTransform`'s `end()` now stashes the decoded result in
`_bufferedOut` and `_endQueued`, then flushes on first
`data`-listener attach (or `resume()`). Mirror of the IM fix.
Same shape applied to `_mkDeflateTransform`. Existing
`zlib_deflate_smoke.js` and `pako_smoke.js` keep passing — those
attach data listeners synchronously and are unaffected.

### `process.stdout` / `process.stderr` are real `Writable` streams

C++ still creates the raw fd-backed Objects with `write` / `fd` /
`isTTY` / `columns` / `rows`. At JS bootstrap (after the stream
module is in place), both streams are replaced with `_Writable`
wrappers whose `_write` delegates to the original raw write. Now
`process.stderr instanceof Stream === true`; npm's config
validator accepts it; `Gauge.setWriteTo(process.stderr)` works.

### `process.getuid` / `getgid` / `geteuid` / `getegid`

`src/node_compat/process.cpp`: thin POSIX wrappers — `getuid(2)`
etc. tar's `preserveOwner` gate, pacote's `selfOwner`, and
npm-lifecycle install scripts all branch on these. Smoke:
[`test/process_getuid_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.92/test/process_getuid_smoke.js).

### `fs.{writeFile,appendFile,copyFile,chmod}Sync` throw Node-shaped errors

`src/node_compat/fs.cpp`: the four remaining sync syscall sites
that were throwing bare `Error` (no `.code` / `.syscall` / `.path`)
now route through `ThrowFsError`. Cosmetic — affects code that
does `catch (e) { if (e.code === 'EACCES') ... }`.

### `tls_cloudflare_smoke` endpoint swap

`test/tls_cloudflare_smoke.js` now targets
`cdn.jsdelivr.net/npm/jquery@3.7.1/dist/jquery.min.js` (~87 KB)
instead of `www.cloudflare.com`'s ~1 MB HTML. Same regression
coverage (well past the 32 KB BIO stall threshold), much less
flake — Cloudflare's IAH edge serves the G3 reliably where the
DFW edge for www.cloudflare.com was rate-limiting. Pinned to
`@3.7.1` (npm immutability). FAIL-on-regression-signature /
SKIP-on-flake shape preserved.

## What's still pending

- **Full `npm install <name>` from registry still hangs.** Even
  with all three stream fixes above, the npm-cli + figgy-config +
  pacote + make-fetch-happen + cacache pipeline hits a
  "cb() never called!" after `silly install readLocalPackageData`.
  A direct `pacote.manifest(spec, simpleOpts)` call succeeds; the
  hang surfaces only when `figgy-config` bakes in the full npm
  config bundle (`Promise: BB`, retry/agent/cache options, etc.).
  Investigation continued in pass 7.
- **`fs.promises.read` / `fs.promises.write`** `{bytesRead, buffer}`
  return shape. Not hit by npm-6.14.18 install path. Add when
  something downstream needs it.
- **ES modules first-class.** Needs SM 60+; long-term.

## Compatibility

Same SpiderMonkey, same OpenSSL, same JIT. Existing v0.91 scripts
run unchanged. The IM-buffering, gunzip-buffering, and stdio-stream
fixes are strictly additive — pre-fix behaviour was "drop bytes /
throw on undefined writeTo"; post-fix is "buffer until listener
attaches / accept process.stderr in config validation".
