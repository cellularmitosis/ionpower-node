# ionpower-node 0.31 — WebCrypto Ed25519 + X25519

Extends SubtleCrypto with the two curve25519-based algorithms. Both
share v0.30's tweetnacl lazy-load plumbing.

## What's new

### Ed25519 via `crypto.subtle`

```js
const { publicKey, privateKey } = await crypto.subtle.generateKey(
    { name: 'Ed25519' }, true, ['sign', 'verify']);

const sig = await crypto.subtle.sign({ name: 'Ed25519' }, privateKey, data);
const ok  = await crypto.subtle.verify({ name: 'Ed25519' }, publicKey, sig, data);

const jwk = await crypto.subtle.exportKey('jwk', publicKey);
// { kty: 'OKP', crv: 'Ed25519', x: '...', ext: true, key_ops: [...] }
```

- `sign` returns a 64-byte ArrayBuffer.
- `importKey('jwk', ...)` accepts OKP JWKs with `x` (public) or `d`
  (32-byte seed for private — auto-expanded to the full 64-byte
  secretKey).
- `exportKey('jwk', key)` emits OKP JWKs; for private keys, both `d`
  (seed) and `x` (derived public) are included.

### X25519 ECDH via `crypto.subtle`

```js
const alice = await crypto.subtle.generateKey({ name: 'X25519' }, true, ['deriveBits']);
const bob   = await crypto.subtle.generateKey({ name: 'X25519' }, true, ['deriveBits']);

const secretA = await crypto.subtle.deriveBits(
    { name: 'X25519', public: bob.publicKey }, alice.privateKey, 256);
const secretB = await crypto.subtle.deriveBits(
    { name: 'X25519', public: alice.publicKey }, bob.privateKey, 256);
// secretA === secretB (curve25519 ECDH)
```

Backed by `nacl.scalarMult(priv, peerPub)`. Length argument truncates
the 32-byte shared secret (256-bit gives the full raw secret).

## Still missing

- RSA / ECDSA / NIST ECDH (P-256, P-384, P-521) — require bignum /
  curve arithmetic we haven't written.
- PKCS#8 / SPKI key formats.
- `deriveKey` (can be composed via `deriveBits` + `importKey`).
