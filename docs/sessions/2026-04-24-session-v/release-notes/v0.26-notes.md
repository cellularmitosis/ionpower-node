# ionpower-node 0.26 — perf_hooks + global performance

Adds the Node `perf_hooks` core module and the WHATWG-compatible
`performance` global.

## What's new

### `globalThis.performance`

```js
const t0 = performance.now();
// ... work ...
const t1 = performance.now();
console.log("took", t1 - t0, "ms");
```

`performance.now()` returns monotonic ms since process start.
`performance.timeOrigin` is `Date.now()` captured at that start.

`mark` / `measure` / `clearMarks` / `clearMeasures` / `getEntries` /
`getEntriesByName` / `getEntriesByType` are all callable with
spec-shaped return types (entries are always empty arrays — we
don't retain timing data).

### `require('perf_hooks')`

```js
const { performance, PerformanceObserver, constants } = require("perf_hooks");

const obs = new PerformanceObserver(entries => { /* … */ });
obs.observe({ entryTypes: ["measure"] });
obs.disconnect();
```

`PerformanceObserver` constructs; `observe` / `disconnect` /
`takeRecords` are no-ops (no entry callbacks fire). `constants`
exposes the Node GC reason enums.

## Resolution

Millisecond resolution — we synthesize from `Date.now()`. SM45
doesn't expose `clock_gettime` directly, so sub-millisecond precision
isn't available. Sufficient for per-request timing and coarse
benchmarks.

## Verified

7 smoke assertions pass on G3 / G4 / G5:
- perf_hooks surface
- performance.now() basics (monotonic, non-negative)
- `globalThis.performance === perf_hooks.performance`
- mark / measure / clearMarks / clearMeasures / getEntries (stubs)
- PerformanceObserver ctor + observe / disconnect / takeRecords
- timeOrigin is a reasonable value (≤ Date.now(), within the hour)
- performance.now() around a 100k-iter loop returns a non-negative delta
