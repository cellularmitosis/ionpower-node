# ionpower-node 0.32 — library hunt wave 6

Nine more vendored libraries under smoke coverage. Three are freshly
vendored; six were already in `test/vendor/` awaiting a smoke.

## New smokes

| Library | Shape verified |
|---|---|
| `ms` | `ms('2 days')` → 172800000; `ms(60000)` → `'1m'` round-trip |
| `picocolors` | `.red('hello')` returns a string containing the input |
| `clsx` | Strings, object-truthiness, array of mixed → space-joined |
| `escape-goat` | Loads; escape function present |
| `strnum` | `'42'` → 42, `'3.14'` → 3.14, `'hello'` → `'hello'` |
| `punycode` | `'bücher.example'` ↔ `'xn--bcher-kva.example'` |
| `ansi-colors` | `.red('hi')` wraps input (NEW — vendored alongside its `symbols.js` companion) |
| `charenc` | `.utf8.stringToBytes('abc')` → `[97,98,99]` (NEW) |
| `tiny-lru` | LRU cache with max size enforced (NEW) |

The `ansi-colors` companion file gets renamed to
`ansi-colors-symbols.js` so our flat `test/vendor/` tree finds it;
the reference in `ansi-colors.js` is path-patched.

## Totals

## Install

```
tar -C /opt -xzf ionpower-node-0.32-g5-ppc.tar.gz
/opt/ionpower-node-0.32/bin/node script.js
```

## Known flakes

`event_loop_smoke.js`'s "earlier timer first" assertion has a
timing-sensitive setTimeout(20)/setTimeout(40) ordering check. It
occasionally trips on the G5 under load even though the underlying
behaviour is correct; a retry passes cleanly. Not a regression —
predates this release.
