# ionpower-node 0.34 — readline core module

Adds Node's `readline` core on top of our existing streaming stdin.

## What's new

```js
const readline = require("readline");
const rl = readline.createInterface({ input: process.stdin });

rl.on("line", (line) => console.log("got:", line));
rl.on("close", () => console.log("end of input"));
```

### Interface surface

- `readline.createInterface({ input, output })` → `Interface`
- `rl.on('line', fn)` / `rl.on('close', fn)` (via EventEmitter)
- `rl.close()` — cleanly unhooks the input stream listeners
- `rl.question(prompt, cb)` — writes prompt, resolves cb on next line
- `rl.pause()` / `rl.resume()` — delegate to input stream
- `rl.setPrompt(p)` / `rl.prompt()` — emit stored prompt to output

Line framing: splits on `\n`; trailing `\r` is stripped (so CRLF
from Windows tools still reads cleanly). Tail bytes at EOF (unterminated
line) are emitted before `'close'` fires.

### Cursor helpers

`cursorTo`, `moveCursor`, `clearLine`, `clearScreenDown` emit ANSI
CSI codes when the target stream is a TTY; no-op otherwise. Matches
the "write to a non-TTY and get nothing weird in the output" Node
behaviour.

## Verified

Three smoke assertions on G3 / G4 / G5:
- Piped stdin: 4 newline-separated lines round-trip through `rl.on('line')`
  and the `'close'` event fires with the right count.
- TTY cursor helpers emit the expected CSI sequences (`\x1b[1G`, `\x1b[2K`).
- Non-TTY streams see zero writes from the same helpers.
