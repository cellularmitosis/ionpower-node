# ionpower-node 0.30 — Ed25519 sign/verify

**First asymmetric crypto primitive.** Wires Node-style
`crypto.sign` / `crypto.verify` / `crypto.generateKeyPair{,Sync}` /
`crypto.createPrivateKey` / `crypto.createPublicKey` through the
tweetnacl pure-JS library for Ed25519.

RSA, ECDSA, ECDH, and X25519 still throw not-supported.

## What's new

```js
const crypto = require('crypto');

const { publicKey, privateKey } = crypto.generateKeyPairSync('ed25519');

const msg = Buffer.from("hello, ed25519!", "utf8");
const sig = crypto.sign(null, msg, privateKey);   // 64 bytes

if (crypto.verify(null, msg, publicKey, sig)) {
    console.log("verified");
}
```

### Key object surface

`generateKeyPairSync('ed25519')` returns two `KeyObject`s with:

- `.type` — `'public'` or `'private'`.
- `.asymmetricKeyType` — `'ed25519'`.
- `.export()` — raw bytes (32 for public, 64 for private).
- `.export({ format: 'jwk' })` — OKP JWK:
  ```js
  { kty: 'OKP', crv: 'Ed25519', x: '...', d: '...' }
  ```

### Import

- `createPublicKey(raw32Bytes | OKP_JWK | privateKey)` — accept raw,
  a JWK, or project from a `KeyObject` of `type: 'private'`.
- `createPrivateKey(raw64Bytes | seed32Bytes | OKP_JWK)` — a 32-byte
  seed is expanded via `nacl.sign.keyPair.fromSeed` into a full
  64-byte secret key.

## Mechanics

- `tweetnacl.js` is lazy-loaded via `__make_require__(cwd)` on first
  call. That path uses the vendor-fallback, so installed binaries
  pick up `share/ionpower-node/vendor/tweetnacl.js` and dev trees hit
  `test/vendor/tweetnacl.js`.
- `tweetnacl.setPRNG(...)` is wired to `crypto.randomBytes` — key
  generation is actually random, not the "no PRNG set" stub.
- `make install` now copies `tweetnacl.js` into `share/ionpower-node/
  vendor/` alongside `babel.js`.
