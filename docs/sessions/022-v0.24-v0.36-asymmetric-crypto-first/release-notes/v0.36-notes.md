# ionpower-node 0.36 — `node:test` minimal runner + `process.exitCode`

Two small but impactful additions.

## What's new

### `require('node:test')` / `require('test')`

Minimal TAP-style test runner:

```js
const test = require('node:test');
const assert = require('assert');

test('sync pass', () => {
    assert.equal(2 + 2, 4);
});

test('async pass', async () => {
    await something();
});

test('nested', (t) => {
    return t.test('inner', () => {
        assert.ok(true);
    });
});

test.skip('broken for now', () => {
    throw new Error("won't run");
});
```

Output is TAP 13:

```
TAP version 13
1..5
ok 1 - sync pass
ok 2 - async pass
    ok - inner
ok 3 - nested
not ok 4 - should fail
  ---
  message: deliberate failure
  stack:   |-
    (stack frames)
  ...
ok 5 - broken for now # SKIP
# pass 4
# fail 1
```

Any `not ok` sets `process.exitCode = 1`, so `--test` / CI pipelines
see a non-zero exit.

### `process.exitCode` is now honoured

`main.cpp` reads `process.exitCode` on shutdown and returns that to
the OS if non-zero. Previously only the entry script's success/failure
drove the exit code, so libraries that set `process.exitCode = 1` on
their way out (tape, node:test, user scripts) appeared to succeed.

## Verified

- 3 sync / 1 async / 1 deliberate-failure / 1 skip / 1 nested test
  produce the correct TAP output.
- Child script with a failing test exits 1 (not 0).
- Skipped test marked `# SKIP`.
- `require('node:test') === require('test')`.
