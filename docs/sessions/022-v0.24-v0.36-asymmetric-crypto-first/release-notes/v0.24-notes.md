# ionpower-node 0.24 — WHATWG Streams

Adds `ReadableStream`, `WritableStream`, and `TransformStream` as
global constructors. Minimal WHATWG Streams shape — enough for the
common consumer patterns.

## What's new

### ReadableStream

```js
const rs = new ReadableStream({
    start(controller) { controller.enqueue("a"); controller.close(); },
    pull(controller)  { … },
    cancel(reason)    { … }
});

const reader = rs.getReader();
const { value, done } = await reader.read();
```

Supports: `start`/`pull`/`cancel` sources, `controller.enqueue`/`close`/
`error`, `getReader().read()/releaseLock()/cancel()`, `locked` flag,
`cancel()`, `tee()`, `pipeTo()`, `pipeThrough()`.

### WritableStream

```js
const ws = new WritableStream({
    start(controller) { … },
    write(chunk, controller) { … },
    close() { … },
    abort(reason) { … }
});

const w = ws.getWriter();
await w.write("x");
await w.close();
```

Writes are serialized to the sink via a per-stream Promise chain —
the sink sees chunks in order, next write only starts after the
previous settles. Supports `getWriter().write/close/abort/releaseLock`
plus `stream.abort(reason)`.

### TransformStream

```js
const upper = new TransformStream({
    transform(chunk, controller) { controller.enqueue(chunk.toUpperCase()); }
});

rs.pipeThrough(upper).pipeTo(ws);
```

Bundles a writable + readable side with `start`/`transform`/`flush`
hooks.

## Backpressure caveat

No explicit high-water-mark queuing or `desiredSize` gauge. Readers /
writers serialize by waiting on the previous Promise. That's enough
for the common consumer patterns (read-all, pipe-through, pipe-to)
but under-spec for producer-heavy scenarios where backpressure is the
point.
