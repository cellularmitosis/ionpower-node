# ionpower-node v0.95 — Node 10 streams: full 22/22 conformance

v0.95 closes the last 5 parked Node 10 stream tests from v0.94. The
handwoven `_Stream` / `_Readable` / `_Writable` / `_Transform` chain
in [`src/node_compat/globals.cpp`](../../../src/node_compat/globals.cpp)
now passes **all 22 of the official Node 10.24.1 `test-stream-*.js`
conformance tests** vendored under
[`test/node10-streams/`](../../../test/node10-streams/) — up from 17
/ 22 in v0.94.

Driven by [`docs/sessions/043-node-10-parity-pass-9-and-express-discovery/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.95/docs/sessions/043-node-10-parity-pass-9-and-express-discovery/notes.md).

## What landed (5 fixes)

### 1. `emittedReadable` dynamic flag (+ `read(0)` consume bug)

`_readableState.emittedReadable` now transitions per Node's contract:

- `false` initially
- `true` immediately before `emit('readable')` fires
- `false` after `read(n)` with non-zero n (or no n)
- unchanged by `read(0)` (refill-only)
- always `false` in flowing mode

Fix gated by `test-stream-readable-emittedReadable`.

Adjacent fix: `read(0)` previously consumed a chunk from the buffer
when the buffer was non-empty (because the existing `n < buffer.length`
branch shifted the buffer for any n). Per Node's contract, `read(0)`
is a refill-trigger — it should return `null`, not consume. Fixed.

### 2. String → Buffer conversion in push()

In non-objectMode without a decoder set, a `push(stringChunk)` now
converts to a `Buffer` (default utf8, or the second arg if provided)
before buffering. This matches Node v10's `readableAddChunk`. Without
it, `push('foo') + push('bar') + read()` returned the joined string
where Node returns `Buffer.from('foobar')` — broken by
`test-stream-readable-emittedReadable`.

### 3. Encoding support: `Readable({encoding})` + `setEncoding(enc)` + decoder in push()

- `new Readable({ encoding: 'utf16le' })` now wires a `StringDecoder`
  into the Readable's state.
- `setEncoding(enc)` installs a decoder on an already-constructed
  Readable.
- `push(BufferChunk)` runs Buffer chunks through the decoder when one
  is set, producing strings.

Tested via `test-stream-decoder-objectmode` (utf16le path). The
existing `StringDecoder` already handles utf16le via Buffer's encoding
machinery.

### `Readable.from()` defaults to objectMode

A consequence of fix 2: `stream.Readable.from(input)` was constructing
a paused, non-objectMode Readable, which meant the new
string→Buffer conversion now applied. Node's `Readable.from`
defaults to `objectMode: true` — chunk identity is preserved.
Fixed.

### 4. `resumeScheduled` dynamic flag

`_readableState.resumeScheduled` now transitions per Node's contract,
implemented to coexist with our sync-flow design:

- `false` initially
- `true` synchronously after `r.resume()` / `r.pipe(w)` / `r.on('data',...)`
- `false` inside the `'data'` listener body (which fires synchronously
  from `_emitFlow`)
- `false` on nextTick, AND inside the deferred `'resume'` event listener

Implementation: keep `_emitFlow` synchronous (streams_smoke depends on
sync data emission after `on('data')`), but bookend the call with
flag bookkeeping. `resume()` clears the flag before flow, sets it to
true after, schedules a nextTick that resets it to false and emits
`'resume'`. Deferring the emit catches `r.on('resume', ...)`
listeners attached AFTER `r.resume()`.

Gated by `test-stream-readable-resumeScheduled`.

### 5. Legacy pipe-cleanup listener model

`Stream.prototype.pipe` now installs the full Node v0.x legacy
listener set:

- `src.on('end', onend)` — drives `dest.end()` (existing).
- `src.on('close', onclose)` — drives `dest.destroy()` (new).
- `src.on('error', onerror)` — cleanup + conditional re-emit (refactored).
- `src.on('data', ondata)` — existing.
- `src.on('end', cleanup)` — new.
- `src.on('close', cleanup)` — new.
- `dest.on('close', cleanup)` — new.

`cleanup` is a per-pipe closure that removes every listener installed
by THIS pipe call (by function identity, so sibling pipes are
untouched). `unpipe()` extended to remove the new listeners.

`onerror` is **not** installed on dest — keeping our pass-8 "re-emit
to dest when src has no error listener" semantics. Otherwise
`w.emit('error')` would fire `onerror`'s re-emit and double-deliver
the error to the user's `dest.on('error')` listener
(`test-stream-pipe-error-handling` subtest 4 surfaced this).

Gated by `test-stream-pipe-cleanup`.
