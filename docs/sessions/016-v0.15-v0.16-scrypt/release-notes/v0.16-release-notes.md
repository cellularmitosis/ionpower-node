# ionpower-node 0.16 — scrypt

Completes the password-hashing crypto surface. `crypto.scryptSync` /
`crypto.scrypt` go from throwing stubs to real RFC 7914 implementations.

**RFC 7914 test vector 1** (P="" S="" N=16 r=1 p=1 dkLen=64) passes
byte-for-byte.

## What's new

Pure-JS implementation, ~150 LOC:

- **Salsa20/8** — 20-round Salsa/20 reduced to 8 rounds, operating
  on 16 × 32-bit words.
- **BlockMix** — the inner mixing step that hashes 2*r × 64-byte
  sub-blocks and reorders them.
- **ROMix** — the memory-hard outer loop (fills V[N], then hashes N
  times with random-access reads from V).
- **scrypt** — PBKDF2-HMAC-SHA256 bookending ROMix over p parallel
  blocks.

### Usage

```js
var crypto = require('crypto');

// Node default params (N=16384 r=8 p=1) — slow on PPC but runs.
var dk = crypto.scryptSync('password', 'salt', 64);

// Light params for tests:
var dk2 = crypto.scryptSync('pw', 's', 32, { N: 1024, r: 8, p: 1 });

// Async variant:
crypto.scrypt('password', 'salt', 64, { N: 1024 }, function (err, dk) {
    console.log(dk.toString('hex'));
});
```

### Warnings

- **Memory-hard**: `N × r × 128` bytes of RAM. Default Node params
  (N=16384 r=8) = 16 MB. Use smaller N on memory-constrained hosts.
- **CPU-intensive**: Salsa20/8 is fast but N×2 blockmix calls adds
  up. A G3 can do default-params scrypt in about 30 seconds, not a
  fraction of a second like a modern x86.
