# ionpower-node v0.97

**Headline: `require('express')` works end-to-end on real PowerPC.**
A real Express server boots, listens, serves JSON, and closes cleanly
on a 900 MHz iBook G3 running Mac OS X 10.4 Tiger.

The blocker that pass-10's `npm install express` discovery surfaced —
`depd` (a transitive dep of every Node-10-era Express app) failing at
`callSite.getFileName is not a function` — turned out to be a missing
V8 structured-frame API. Fixed; closed off the v0.96 follow-up gap.

## Fix

**V8 `Error.prepareStackTrace` + `CallSite` shim**
([`src/node_compat/globals.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v0.97/src/node_compat/globals.cpp)).

Replaced the v0.96 "set `.stack` to a SM-format string" stub with a
proper V8-shape implementation:

```js
var obj = {};
var prep = Error.prepareStackTrace;
Error.prepareStackTrace = function (err, frames) { return frames; };
Error.captureStackTrace(obj);
var stack = obj.stack;          // <-- Array<CallSite>, lazy
Error.prepareStackTrace = prep;
```

`Error.captureStackTrace(target, constructorOpt)` now parses the SM45
stack string at capture time, then installs `target.stack` as a lazy
accessor: on first read, if `Error.prepareStackTrace` is a function,
it's called with `(target, frames)` and the result is cached;
otherwise the cached value is a V8-style
`Error[: msg]\n    at func (file:line:col)\n…` string.

Each frame implements the 13 V8 CallSite methods that Node-land
libraries actually use:

```
getFileName       getLineNumber    getColumnNumber  getFunctionName
getMethodName     getTypeName      getEvalOrigin    isToplevel
isEval            isNative         isConstructor    getThis
getFunction       toString         isAsync          isPromiseAll
getPromiseIndex   getScriptNameOrSourceURL
```

`constructorOpt` is honoured: frames at and above the first frame
whose function name matches `constructorOpt.name` are dropped, which
is how V8 lets a custom-error constructor hide itself from its own
`new Error()` stack.

Eval frames are detected via SM45's `" line N > eval"` filename
suffix; `isEval()` returns true and `getEvalOrigin()` returns the
original full filename.

## What this unblocks

`require('express')` against `express@4.22.2` (the Node-10-era pin)
now loads cleanly via the existing npm-installed tree from v0.96.
Confirmed end-to-end on a G3:

```js
var express = require("express");
var app = express();
app.get("/health", (req, res) => res.json({ ok: true }));
var server = app.listen(3789, () => {
  http.get("http://127.0.0.1:3789/health", (res) => {
    /* status: 200 body: {"ok":true,"host":"ibookg37"} */
    server.close(() => process.exit(0));
  });
});
```

Generalises to every Node-10-era library that uses
`Error.captureStackTrace + Error.prepareStackTrace`: depd, mocha,
sinon, jest's stack formatter, error-ex, …

## Demo

New `demos/express-chat-npm/`
([`demos/express-chat-npm/`](https://github.com/cellularmitosis/ionpower-node/tree/v0.97/demos/express-chat-npm)):
same anonymous chat board as `demos/express-chat/` but pulls
`express` + `handlebars` + `ws` via `npm install` from the live
registry instead of from the vendored test tree.

```bash
cd /opt/ionpower-node-0.97/share/ionpower-node/demos/express-chat-npm
node ../../test/vendor/nm/node_modules/npm/cli.js install   # ~4 min
node server.js 8080
```

The vanilla `demos/express-chat/` still ships unchanged — it's the
~5-second-to-screen version. The npm variant is the proof that the
runtime hosts arbitrary modern Node code from the registry.

## Verification

- All 14 core smokes pass on G3 — incl. new `test/callsite_smoke.js`
  (7 assertions exercising the V8 idiom).
- All 495 / 0 libs smokes pass on G3 (no regressions from v0.96).
- `require('express')` on `express@4.22.2`: module loads, app
  constructs, three routes register, `app.listen(3789)` succeeds,
  `GET /health` round-trips a JSON body, `server.close()` runs the
  callback.

## Carryover

- `fs.promises.read` / `write` return shape — still pending since
  v0.92.
- `execa/lib/errname: unable to establish process.binding('uv')`
  warning at end of `npm install`. Cosmetic.
- `express@5` end-to-end: Babel-on-parse-error is wired (since v0.85)
  and the IE-11 preset lowers object spread, but the v5 path hasn't
  been driven all the way through `require + listen` yet. Likely a
  follow-up session.
- Prototype-mutation warning from `express/lib/router/index.js:51` —
  SM emits one warning at startup. Cosmetic.
