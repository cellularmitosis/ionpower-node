## What's new

`os.cpus`, `os.hostname`, `os.loadavg`, `os.totalmem`, `os.freemem`
all return real values now. Up to v0.71 they were placeholders
(`os.cpus()` claimed "PowerPC G4" at 1000 MHz on every host;
`os.totalmem()` returned a hardcoded 1 GB).

### Probe sources

| API | Source |
|---|---|
| `os.cpus()`        | `sysctl -n hw.cpusubtype hw.cpufrequency hw.ncpu`; Mach-O subtype maps to G3 (750) / G4 (7400/7450) / G5 (970) |
| `os.hostname()`    | `$HOSTNAME` env, else `/bin/hostname`, else `'localhost'` |
| `os.loadavg()`     | parse `/usr/bin/uptime` for the load-average triple |
| `os.totalmem()`    | `sysctl -n hw.memsize` |
| `os.freemem()`     | `(Pages free + Pages speculative) * page size` from `/usr/bin/vm_stat` |

`cpus` / `hostname` / `totalmem` cache after first call; `loadavg`
/ `freemem` re-probe every call (they change).

### Why it matters

Banner-style output ("served by ionpower-node-0.72 on ibookg37
(ppc, PowerPC G3 (750))") now actually says the hardware. Same for
any monitoring code that reads `os.cpus()[0].model` or
`os.totalmem()` to decide whether to enable a memory-hungry path.

### What we see now

On the new canonical G3 build host (ibookg37, iBook G3 900 MHz):

```
os.cpus()    = [{ model: 'PowerPC G3 (750)', speed: 900, times: ... }]
os.hostname() = 'ibookg37.home'
os.loadavg() = [1.02, 0.82, 0.7]
os.totalmem() = 671088640 bytes  (640 MB)
os.freemem()  = 102739968 bytes  (98 MB)
```

## Demos shipped this release

- `examples/chat/` — multi-client WebSocket chat, runnable on any
  triad host. The demo banner now reports real CPU info thanks to
  this release's `os.cpus()`.
- `examples/npm-fetch/` — fetch + decompress + extract + require
  an npm package directly from `registry.npmjs.org`. Demonstrates
  the v0.66-v0.71 stack (fetch, zlib gunzip, fs, require) is
  enough to consume the live npm ecosystem.

## Triad

ibookg37 (iBook G3 900 MHz, **first run as the canonical G3 host**),
emac (G4 7450), pmacg5 (G5 970) — all green. 1915+ assertions across
423 smoke files.
