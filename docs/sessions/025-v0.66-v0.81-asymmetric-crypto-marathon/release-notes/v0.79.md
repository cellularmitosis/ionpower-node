## What's new

WebCrypto catches up to the Node-side ECDSA + NIST ECDH that landed
in v0.75 and v0.76:

```js
const pair = await crypto.subtle.generateKey(
    { name: 'ECDSA', namedCurve: 'P-256' },
    true,
    ['sign', 'verify']
);

const sig = await crypto.subtle.sign(
    { name: 'ECDSA', hash: 'SHA-256' },
    pair.privateKey,
    new TextEncoder().encode('hello')
);

const ok = await crypto.subtle.verify(
    { name: 'ECDSA', hash: 'SHA-256' },
    pair.publicKey,
    sig,
    new TextEncoder().encode('hello')
);                                                // true
```

```js
const alice = await crypto.subtle.generateKey({ name: 'ECDH', namedCurve: 'P-256' }, true, ['deriveBits']);
const bob   = await crypto.subtle.generateKey({ name: 'ECDH', namedCurve: 'P-256' }, true, ['deriveBits']);

const sharedAlice = await crypto.subtle.deriveBits(
    { name: 'ECDH', public: bob.publicKey },
    alice.privateKey,
    256
);
// sharedAlice equals the symmetric derive on bob's side
```

Curves: P-256, P-384, secp256k1. (P-521 works at the elliptic level
but is glacial on G3 — ~30 s per verify — so it's not smoke-tested.)

### Why this matters

Browser-style code that uses `crypto.subtle` (the modern alternative
to Node's `crypto.{sign,verify}`) now works without library shims.
That includes the `jose` family of JWT libraries (when configured
to use WebCrypto), modern OAuth flows, and any code that targets the
WebCrypto-or-Node convergence pattern.

### Internals

- `_CryptoKey` gains an optional `_keyObject` field that carries our
  Node-shape KeyObject for EC keys. `subtle.{sign,verify,deriveBits}`
  delegate via that handle to the existing `_ecdsaSign` /
  `_ecdsaVerify` / `_ecdhDerive` helpers.
- `_ecdsaDerToRaw` + `_ecdsaRawToDer` convert between Node's DER
  signatures and WebCrypto's raw `r ‖ s` (left-padded to the curve
  byte length, with proper non-negative DER encoding when the high
  bit is set).
