v0.88 bundles two passes of Node-10 parity work — the wave-1 surface
that v0.87 closed (release deferred), plus the pass-2 install-pipeline
work that pushes npm 6.14.18 from "module-load fails at resolve-from"
to "runs end-to-end through `Installer.commit` and only stops at the
TLS-to-Cloudflare and minizlib-internal-handle layers."

## Summary

Tests grew from 458 (v0.86) to 463 (v0.88, +5 new smokes). G3 + G4 +
G5 triad-builds clean. `npm install` is materially closer to working
end-to-end but not yet there — pass-3 captures the remaining gaps.

## What's new (pass-1 + pass-2 combined)

### `process.version` policy: `v10.24.1`

`process.version` previously reported `'ionpower-node-0.NN'` — a
deliberate "we are not Node" identifier. The cost showed up immediately
in any library that semver-parses it (npm's `semver.satisfies`,
yargs-parser, `engines` checks). Going forward `process.version`
reports `'v10.24.1'` (the last Node 10 release). The runtime's own
identity moves to `process.versions['ionpower-node']` (bracket access —
the dash makes it dotless-illegal). See
[`docs/plans/node-target-version.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/docs/plans/node-target-version.md)
for the policy decision.

### `process.execPath`, `process.binding(name)` stub, `require('constants')`

`process.execPath` now reports the absolute path to the runtime binary
(mirrors `process.argv[0]`). `process.binding(name)` returns an empty
object stub for any name (libraries probe-feature it; throwing was
worse than returning {}). `require('constants')` now seeds a real set
of `O_*`, `S_IF*`, errno values — graceful-fs's `O_SYMLINK` probe
needs the real value.

### Module class: `_nodeModulePaths` + `_resolveFilename`

Two private-but-load-bearing Node Module-class entries that npm
internals reach for. `Module._nodeModulePaths(from)` walks ancestors
producing the `node_modules/` search list; `Module._resolveFilename(spec,
parent)` resolves a specifier to an absolute path WITHOUT loading
(distinct from our existing `__require_native__` which loads-on-resolve).
Both mirrored onto the `require('module')` wrapper-object form too —
that's the shape `resolve-from` calls.

Underneath `_resolveFilename` is a new C++ JS-callable
`__resolve_native__(dir, spec)` that runs the same resolver as
`__require_native__` but skips the file-load step.

Smokes: [`test/module_node_paths_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/module_node_paths_smoke.js),
[`test/module_resolve_filename_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/module_resolve_filename_smoke.js).

### Module cache: live `.exports` (circular requires are now Node-correct)

The require cache used to store the raw exports object snapshotted at
module-load entry. When user code did `module.exports = X`, circular
requires that hit the cache during the wrapper's evaluation got the
ORIGINAL `{}` — not X. This bit npm hard: `lib/utils/metrics.js` does
`const npm = require('../npm.js')` while npm.js is still evaluating;
the captured `npm` ended up being a pre-`module.exports = new
EventEmitter()` empty `{}`, and `npm.config = …` went onto a different
object — so `npm.config` was undefined for the rest of the run.

Now the cache stores the MODULE WRAPPER for file-path keys; `LookupCache`
returns `module.exports` from it, so circular requires see the live
value. The C++ change is mirrored by a JS-side update to the
`__make_require__` wrapped require (which short-circuits cache hits)
to discriminate by key shape.

Smoke: [`test/circular_require_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/circular_require_smoke.js).

### `fs` additions

- `fs.{open,close,read,write}{Sync,async}` — the low-level fd-based
  fs APIs. `fs.readSync` / `fs.writeSync` accept Uint8Array buffers
  with offset+length+position; the async forms specialize so
  `cb(err, bytes, buffer)` matches Node's contract (bluebird's
  `promisify({multiArgs: true})` needs all three values). Smoke:
  [`test/fs_fd_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/fs_fd_smoke.js).
- `fs.{truncate,chown,utimes,fchmod,symlink}` (sync + async) and
  `fs.readlink`/`readlinkSync` backed by real `readlink(2)`. `lchown`
  aliased to `chown` (matches existing `lstat = stat` approximation).
  Smokes: [`test/fs_extras2_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/fs_extras2_smoke.js),
  [`test/fs_readlink_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/fs_readlink_smoke.js).
- `fs.readdirSync` errno code: opendir-failure now produces a
  Node-shaped Error with `.code = 'ENOENT'` (or appropriate errno).
  Without this, `glob` and `graceful-fs` treated `er.code === undefined`
  as a fatal "unknown" error instead of silently caching the missing
  dir as not-found.

### `util.debuglog` + `util._extend`

Both are stable Node utilities npm internals call at module-load
time. Without them, `agentkeepalive`'s `util.debuglog('http')` and
the npm install pipeline's `util._extend(target, source)` calls
threw at the wrong moment and the failures were silently logged
to `npmlog`'s in-memory record buffer (because npmlog was paused
with no flushed stream). Smoke:
[`test/util_debuglog_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/util_debuglog_smoke.js).

### `index.json` resolution

`require('foo')` now tries `<dir>/index.json` after `index.js` /
`index.cjs`. Some packages (`spdx-license-ids`, `spdx-exceptions`)
ship only an `index.json` with no `"main"` in package.json and rely
on this resolution branch. Smoke:
[`test/index_json_resolve_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/test/index_json_resolve_smoke.js).

### `zlib` class-form constructors

Aliased `zlib.{Gzip,Gunzip,Deflate,Inflate,DeflateRaw,InflateRaw,Unzip}`
to the existing `create*` factory functions. minizlib (used by
npm's tarball pipeline) does `new realZlib[mode](opts)` for each
mode. JS contract: `new fn()` returns the function's returned
object when one is returned, so calling our factories with `new`
returns the stream they construct.

## What's still broken

`npm install <pkg-from-registry>` doesn't work. Two distinct gaps:

1. **TLS-to-Cloudflare**: `https.get('https://www.cloudflare.com/')`
   gets status 200 but `SSL_read` fails with "decryption failed or
   bad record mac" on the response body. `https.get('https://registry.npmjs.org/')`
   hangs silently. `https.get('https://example.com/')` works fine
   (~500 ms). Pre-existing, not introduced by pass 2 — but visible
   for the first time because the install pipeline now reaches the
   network layer. Reproducer is one-line.

2. **`zlib._handle._processChunk(chunk, flushFlag)` emulation**:
   minizlib does sync decompression by reaching into our zlib
   stream's `._handle._processChunk` (a real Node internal API
   bound to the C++ binding). Our streams are pure JS; no
   `_handle`. `npm install <local-tarball>` gets all the way
   through pacote → minizlib → first decompression call, then
   trips on `nativeHandle is undefined`. Functional zlib
   (`zlib.gunzipSync(data)` on the same tarball) works correctly
   — only minizlib's specific internal-handle dance is missing.

Both queued for pass 3, captured in
[`docs/sessions/2026-05-10-session-2-node-10-parity-pass-2/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.88/docs/sessions/2026-05-10-session-2-node-10-parity-pass-2/notes.md#pass-3-list-next-session).
