# ionpower-node 0.12 — SHA-512, fetch, dns, HTTP chunked, stdin streaming

A batch release. Five largely-independent features landing together:

1. **SHA-512 + SHA-384** (+ HMAC + PBKDF2 over them)
2. **`fetch`** + **`AbortController`** + **`AbortSignal`** + `Headers` / `Response`
3. **`dns`** module
4. **HTTP chunked** server responses + **keep-alive** pipelining
5. **`process.stdin`** rewritten as a real streaming Readable on `ioWatch`

504 libraries (unchanged). 1231 → **1255+** assertions across 375
smoke files.

## What's new

### SHA-512 / SHA-384

64-bit arithmetic via `[hi, lo]` Uint32 pairs (SM45 has no BigInt on
PPC). Helpers: `_add64`, `_xor64`, `_and64`, `_not64`, `_rotr64`,
`_shr64`. 80 K constants, 80-round compression.

- `createHash('sha512')` / `createHash('sha384')` (+ `sha-512` alias)
- `createHmac` with the correct 128-byte block size
- `pbkdf2Sync` / `pbkdf2` dispatches over md5/sha1/sha224/sha256/sha384/sha512
- FIPS 180-4 + RFC 4231 HMAC-SHA512/384 + PBKDF2-SHA512 vectors verified inline

### fetch + AbortController + AbortSignal

Built on top of v0.10's async `http.request` + v0.11's microtask queue.
Global `fetch`, `Headers`, `Response`, `AbortController`, `AbortSignal`.

```js
const res = await fetch('http://127.0.0.1:8080/api', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({hello: 'world'}),
    signal: AbortSignal.timeout(5000),
});
console.log(res.ok, await res.json());
```

- `Response`: `.text()`, `.json()`, `.arrayBuffer()`, `.buffer()`
- `Headers`: case-insensitive Map-ish
- `AbortSignal.abort(reason)` and `.timeout(ms)` static factories
- HTTPS still falls through to the sync curl helper

### dns

- `lookup` / `resolve` / `resolve4` / `resolve6` via `gethostbyname`
- `promises.lookup` etc.
- MX / TXT / CNAME / SRV / NS return `[]` for compat
- ENOTFOUND propagates properly

### HTTP chunked server responses + keep-alive

`ServerResponse` now picks framing automatically:
- user set Content-Length → length-framed
- `setHeader('Transfer-Encoding', 'chunked')` → explicit chunked
- `.write()` called without Content-Length → auto-chunked
- `.end(body)` with nothing else → buffered

Server handles pipelined keep-alive requests on the same socket:
HTTP/1.1 default keeps the connection open unless `Connection: close`
is set. Parser state is reset between requests and any leftover bytes
become the start of the next request.

### process.stdin on ioWatch

Old v0.10 behavior: first `'data'` listener triggered a one-shot
`fs.readFileSync('/dev/stdin')` → single chunk. New: `ioWatch(0,
READABLE)` streams chunks as they arrive, emits `'end'` on EOF.
`.pause()` unwatches, `.resume()` re-watches, `.pipe()` works.

Unlocks CLI tools that expect stdin to be a real stream (prompts,
line processors, REPL-ish things).

## Install

Each tarball installs to `/opt/ionpower-node-0.12/`.

```
tar -C /opt -xzf ionpower-node-0.12-g5-ppc.tar.gz
/opt/ionpower-node-0.12/bin/node script.js
```

## Known limitations

- HTTPS through `fetch` uses the sync curl shim (no TLS in net yet).
- zlib compression still stubbed.
- scrypt still stubbed.
- `process.nextTick` shares the microtask queue (no strict priority).
