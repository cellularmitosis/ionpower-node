# ionpower-node 0.19 — AES-GCM (authenticated encryption)

Symmetric crypto surface is **complete** for most Node-API use cases.

## What's new

### AES-GCM (NIST SP 800-38D)

Authenticated encryption with associated data (AEAD). Handles all
three key sizes: `aes-128-gcm`, `aes-192-gcm`, `aes-256-gcm`.

- Pure-JS GHASH: GF(2¹²⁸) multiplication with the reducing polynomial
  `0xe1||0^120`. Bit-wise implementation — correct but not fast.
- J0 derivation: `IV || 0^31 || 1` for 96-bit IV; GHASH-based for other IV lengths.
- Tag construction: `GHASH(AAD_padded || C_padded || len(AAD)_64 || len(C)_64)
  XOR AES_encrypt(J0)`.
- Constant-time tag compare on decrypt.
- `setAAD(aad)`, `setAuthTag(tag)`, `getAuthTag()` — Node's API.

**NIST GCM Test Case 3** (AES-128, K=0^128, IV=0^96, P=0^128) passes
byte-for-byte for both ciphertext and auth tag.

```js
var key = crypto.randomBytes(32);
var iv  = crypto.randomBytes(12);

var enc = crypto.createCipheriv('aes-256-gcm', key, iv);
enc.setAAD(Buffer.from('user:alice'));
enc.update('secret data');
var ct = enc.final();
var tag = enc.getAuthTag();

var dec = crypto.createDecipheriv('aes-256-gcm', key, iv);
dec.setAAD(Buffer.from('user:alice'));
dec.setAuthTag(tag);
dec.update(ct);
var pt = dec.final('utf8');  // 'secret data'
```

Decryption throws if the tag doesn't match — proper AEAD semantics.

## Crypto surface

With v0.19 the crypto module is ✅ in the API table. Complete subset:

- **Hashes**: md5, sha1, sha224, sha256, sha384, sha512
- **MAC**: HMAC over all of the above
- **KDF**: PBKDF2, scrypt (RFC 7914), HKDF (RFC 5869)
- **Symmetric cipher**: AES-128/192/256 in CBC, CTR, GCM
- **Entropy**: randomBytes, randomUUID, randomInt
- **Misc**: timingSafeEqual, createSecretKey

Notably absent: `sign` / `verify` (asymmetric — RSA/ECDSA/Ed25519),
TLS.
