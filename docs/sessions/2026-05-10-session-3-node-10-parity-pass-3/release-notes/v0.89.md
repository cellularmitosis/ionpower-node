v0.89 ships nine waves of Node-10 parity work driven by deep tracing
of npm 6.14.18's tarball-install path. Each wave closes a real gap
that surfaced when something downstream of pass-2's runtime hit a
hole. `npm install <local-tarball>` is closer than v0.88 — past
resolve, ideal-tree, and into the extract action — but still doesn't
finish end-to-end (final blocker is a hang inside cacache's pump
pipeline, deferred to pass 4).

Driven by [`docs/sessions/2026-05-10-session-3-node-10-parity-pass-3/notes.md`](https://github.com/cellularmitosis/ionpower-node/blob/v0.89/docs/sessions/2026-05-10-session-3-node-10-parity-pass-3/notes.md).

## Summary

Tests grew from 463 (v0.88) to 467 (v0.89, +4 new smokes). G3 + G4 +
G5 triad-builds clean. The incremental fixes are valuable independent
of the npm install context — every wave addresses a concrete Node-API
contract gap.

## What's new (pass 3)

### `zlib._handle._processChunk` emulation on stream class-forms

`minizlib` (vendored across the npm 6 ecosystem) does sync
decompression by reaching into `this[_handle]._processChunk(chunk,
flushFlag)` on its inner zlib stream — and monkey-patches
`Buffer.concat = (args) => args` BEFORE the call to harvest output
chunks as an array. Our pure-JS zlib streams now expose
`_processChunk` directly on the stream (not on `_handle` — that's
just a stub for the close-swap dance), buffer chunks until
`flushFlag === Z_FINISH (4)`, and use a closure-captured original
`Buffer.concat` to survive minizlib's monkey-patch. Smoke:
[`test/zlib_handle_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.89/test/zlib_handle_smoke.js).

### `path.resolve` collapses `..` segments

The pre-fix `PathResolve` (C++) explicitly disclaimed `..` collapsing
in a comment that was wrong about real Node's behavior. Without the
collapse, `path.resolve('/foo', '..')` returned `'/foo/..'` — npm's
`hasAnyWriteAccess` recursively walks up the directory tree via
`path.resolve(dir, '..')`, never reaches root, and trips our
PATH_MAX guard with `path.resolve: overflow`. Two-pass normalization
now handles `//`, `/./`, AND `/foo/..` segments, with `/..` capped
at root. Smoke:
[`test/path_resolve_dotdot_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.89/test/path_resolve_dotdot_smoke.js).

### `fs.createReadStream` / `createWriteStream` work with `new`

graceful-fs's `ReadStream` wrapper does
`fs$ReadStream.apply(this, arguments), this` — the comma operator
discards our function's return value and uses the empty `this`.
Pre-fix, our factory ignored `this` and built a fresh EventEmitter
for the return; graceful-fs handed cacache/pump the methodless `this`
→ `stream.on is not a function`. Now we detect the new-call
(`this !== fs && typeof this.on !== 'function'`),
`Object.setPrototypeOf(this, EventEmitter.prototype)`, and populate
in place. Plain-call path unchanged. Smoke:
[`test/fs_createstream_new_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.89/test/fs_createstream_new_smoke.js).

### EventEmitter `newListener` / `removeListener` meta-events

Real Node emits `'newListener'` BEFORE adding any listener, and
`'removeListener'` AFTER removing one. Pacote's
`with-tarball-stream.js` uses `'newListener'` for an error-replay
pattern (cache an early stream error in a once() handler, then any
late `.on('error', l)` gets the error replayed). Without the
meta-events, npm install hangs inside extract waiting forever for an
error that's already been emitted. Our EventEmitter now emits both
meta-events with proper recursion guards. Smoke:
[`test/event_newlistener_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.89/test/event_newlistener_smoke.js).

### Stream pump hardening: idempotent destroy, Transform.end ordering, `_final` hook

Three closely-related fixes around stream destruction during pump
cascades:

1. `_Readable.destroy` and `_Writable.destroy` are now idempotent
   (`if (this._destroyed) return; this._destroyed = true;`). pump's
   `destroys.forEach(call)` iterates all destroy fns; without
   idempotency, second/third calls re-emitted `'close'` and tripped
   end-of-stream's "premature close" guard.
2. `_Transform.end` inlines doFinish instead of delegating to
   `_origEnd`. Reason: `push(null)` triggers the readable-side `'end'`
   emission, which (via downstream pipe) can synchronously cascade to
   `.destroy()` on this very stream BEFORE the writable-side
   `ws.ended` gets set. eos.onclose then sees `ws.ended === false` →
   premature close. The new doEnd marks `ws.ended = true` BEFORE
   `push(null)`.
3. The new doEnd ALSO honors the `_final` hook (which the original
   `_origEnd` did via `_Writable.end`). tar's unpacker uses `_final`
   to flush remaining file handles before `'finish'` — skipping it
   makes pacote's tar pipeline hang.

### `fs.{futimes,futimesSync,link,linkSync}`

- `fs.futimes` (POSIX `futimes(2)`): tar's unpacker uses it to
  restore the mtime on freshly-extracted files. Without it, tar
  blows up mid-unpack with `fs.futimes is not a function`.
- `fs.link` (POSIX `link(2)`): npm's `lockfile` uses it for atomic
  lockfile creation. Without it, lockfile crashes with `fs.link is
  not a function` and never releases the staging-dir lock.

Both wired into `fs.promises.*` too.

### `fs.statSync` time fields are Date objects + `ctime` / `atime` / `birthtime`

Two fixes to the stat-result object:
- Time fields (`mtime`, `atime`, `ctime`, `birthtime`) are now Date
  objects (`new Date(ms)`). Real Node returns Dates; npm's lockfile
  does `st.ctime.getTime()`, which fails on a number.
- The C++ side now returns `mtimeMs` / `atimeMs` / `ctimeMs` /
  `birthtimeMs` as raw numbers (matching Node's full surface).
  birthtime is approximated to ctime on POSIX (Tiger doesn't track
  creation time separately).

The existing `_wrapStats` JS wrapper (which also boxes
`isFile`/`isDirectory`/`isSymbolicLink` as methods) now boxes the
times too. One small downstream change: `test/fs_extras2_smoke.js`
switched from `st.mtime / 1000` (numeric div) to `st.mtimeMs / 1000`.

## What's still broken

- **`npm install <local-tarball>` end-to-end.** Gets MUCH further
  than v0.88 (resolve, ideal-tree, manifest-fetch, dep-tree-build,
  staging lock, extract-action-start), then hangs inside cacache's
  `pump(fs.createReadStream(cpath), ssri.integrityStream(...), passThrough)`
  pipeline. Reproduced via tracing; the multi-stage pump pipe never
  resolves nor errors. Each subset reproduces correctly in
  isolation — only the full npm context hangs. Pass-4 entry point.

- **TLS to Cloudflare-fronted endpoints.** Pass-3 hypothesized this
  was a JS-side BIO drop-on-stall in `_onRawData`; the fix didn't
  resolve cloudflare's `ssl3_get_record: decryption failed or bad
  record mac`. example.com still works; the fix isn't a regression —
  but it's not the right fix either. Reverted (didn't ship a
  known-failing smoke). Pass-4 should investigate ALPN, cipher-suite
  list, or TLS 1.3-specific record handling.

## Compatibility

Additive only with two semantic adjustments worth calling out:

- `fs.statSync().mtime` is now a Date, not a number. Use `mtimeMs`
  for the numeric form. Real Node has been Date-typed for years; any
  code that expected a number was already non-portable.
- `_Readable.destroy` / `_Writable.destroy` are now idempotent.
  Anything that depended on `'close'` re-firing on repeated destroy
  calls would now only see it once.

Same SpiderMonkey, same OpenSSL, same JIT. Existing v0.88 scripts
run unchanged.
