# ionpower-node v0.96

**Headline: `npm install express` works end-to-end against the live
registry on real PowerPC hardware.**

The blocker the v0.95 discovery pass surfaced — gunzip `"Data error"`
during npm's metadata fetches — turned out to be a one-character
off-by-one in our embedded tiny-inflate's uncompressed-block byte
alignment. Fixed; ~70 packages install in 3-5 minutes from
registry.npmjs.org through the existing TLS / HTTP / streams /
gunzip stack.

## Fix

**`tinf_inflate_uncompressed_block` byte-alignment off-by-one**
([`src/node_compat/zlib.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v0.96/src/node_compat/zlib.cpp)).

Servers that compress with `Z_SYNC_FLUSH` mid-stream (the npm
registry, via Cloudflare) insert empty stored-block markers
(`00 00 ff ff`) between compressed chunks. To read those markers
the inflater first byte-aligns by rewinding `sourceIndex` and
decrementing `bitcount` by 8 per buffered byte:

```js
// before
while (d.bitcount > 8) { d.sourceIndex--; d.bitcount -= 8; }
// after
while (d.bitcount >= 8) { d.sourceIndex--; d.bitcount -= 8; }
```

When the previous block left `bitcount` at an exact multiple of 8
(8, 16, 24, ...) the `> 8` loop stopped one iteration early,
leaving `sourceIndex` one byte past the LEN low byte of the empty
block — the LEN/NLEN check failed, the inflater threw `"Data error"`,
and any consumer pumping through `zlib.createGunzip()` (i.e. anything
node-fetch-npm fetches that the registry happens to serve with this
alignment) saw the error.

Whether any specific gzip payload tripped it depended on the bit
alignment of the immediately-preceding dynamic-Huffman block.
`express`, `raw-body`, `react`, `body-parser` reproducibly tripped
it; `lodash` did not. Random-data gzips (uncompressed blocks only,
predictable alignment) never tripped it, which is why the bug
escaped earlier conformance runs.

This is a real bug in upstream foliojs/tiny-inflate too — same code
path, same `> 8`. Worth filing once the dust settles.

## Defensive (no behavior change)

`s.end` of both `_mkInflateTransform` and `_mkDeflateTransform`
([`src/node_compat/globals.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v0.96/src/node_compat/globals.cpp))
now uses `_origBufferConcat(chunks)` instead of `Buffer.concat(chunks)`
— matches what `_processChunk` already did. minizlib temporarily
monkey-patches `Buffer.concat` to `(args) => args` around its sync-
decompress dance and restores it synchronously, so cross-call leakage
shouldn't happen — but using the captured reference is free defense.

## Verification

- All 14 core smokes pass on G3.
- All 495 / 0 libs smokes pass on G3 (includes the 22 Node 10 stream
  tests from v0.95).
- `tinflate-stress.js` clean on every payload that previously failed:
  raw-body, express-full, react-full, body-parser-full, ...
- **`npm install express` end-to-end on G3, against the live
  registry**: `+ express@5.2.1`, 66 packages in 254s.
- **`npm install express@4`** also clean: `+ express@4.22.2`,
  68 packages in 188s.

## Next

`require('express')` itself doesn't yet load — two more gaps:

1. **Object spread (`{ ...a, ...b }`)** in modern express's source.
   ES2018, SM45 doesn't parse it. Fix: route user code through Babel
   at require-time on a parse-error retry (we already ship babel.js
   with the runtime).
2. **V8 `CallSite` API** for `Error.captureStackTrace` consumers
   (`depd`, used by express@4 + many Node 10-era libs).

Plus the carryover from v0.92 (`fs.promises.read` / `write` return
shape).
