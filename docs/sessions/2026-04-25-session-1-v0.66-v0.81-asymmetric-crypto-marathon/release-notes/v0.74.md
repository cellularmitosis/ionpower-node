## What's new

### `Buffer.from(ArrayBuffer)` actually preserves the bytes

Up to v0.73, `Buffer.from()` had a bug: when given an ArrayBuffer
input it fell through to the generic array-like branch, which read
`.length` off the input. ArrayBuffer has `.byteLength`, not
`.length` — so `Buffer.from(arrayBuffer)` silently produced a
**0-length** Buffer, breaking the canonical pattern:

```js
fetch(url).then(r => r.arrayBuffer()).then(ab => Buffer.from(ab));
```

This affected `demos/npm-fetch/install.js` (after the v0.73 binary
fetch fix made the underlying ArrayBuffer return real bytes, the
copy into a Buffer was still empty). It would affect any code that
reads binary data over `fetch` or the WHATWG Streams API and copies
through a Buffer.

v0.74 patches `BufferFrom` in `src/node_compat/buffer.cpp` to
explicitly handle:

- **ArrayBuffer**: `JS_GetArrayBufferByteLength` + `JS_GetArrayBufferData`
- **TypedArray** (incl. existing Uint8Array Buffers): `JS_GetTypedArrayByteLength` +
  `JS_GetArrayBufferViewData` — honors a sliced view's `byteOffset` / `byteLength`
- **Array-like fallback** unchanged

## Setup (unchanged from v0.73)

The mozjs tarballs from v0.73 still apply — install once, then drop
v0.74 runtime tarballs in beside them:

```bash
# One-time (skip if you already did this for v0.73)
curl -L -O https://github.com/cellularmitosis/ionpower-node/releases/download/v0.73/mozjs-45-ionpower-g3.tar.gz
sudo tar xzpf mozjs-45-ionpower-g3.tar.gz -C /opt/

# Per release
curl -L -O https://github.com/cellularmitosis/ionpower-node/releases/latest/download/ionpower-node-0.74-g3-ppc.tar.gz
sudo tar xzpf ionpower-node-0.74-g3-ppc.tar.gz -C /opt/
/opt/ionpower-node-0.74/bin/node --version
```

(Ditto with `g4`/`g5` instead of `g3` for those arches.)
