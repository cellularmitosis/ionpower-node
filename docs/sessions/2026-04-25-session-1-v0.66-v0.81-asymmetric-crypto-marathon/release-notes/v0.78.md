## What's new

Closes both remaining "Missing" CommonJS items from v0.71's README.

### `import.meta`

```js
console.log(import.meta.url);       // 'file:///Users/.../app.js'
console.log(import.meta.filename);  // '/Users/.../app.js'
console.log(import.meta.dirname);   // '/Users/.../'
```

Implemented via regex substitutions in the Babel-on-parse-failure
preprocessor:

```
import.meta.url       -> ("file://" + __filename)
import.meta.filename  -> __filename
import.meta.dirname   -> __dirname
import.meta           -> { url, filename, dirname }
```

### Dynamic `import()`

```js
const fs = (await import('fs')).default;
fs.writeFileSync('hello.txt', 'world');

const mod = await import('./helper.js');
mod.default.greet('world');
```

`import(spec)` is regex-rewritten to `__dynamic_import__(spec, require)`,
which returns `Promise.resolve({ default: <require result> })`. The
local `require` is passed in so relative specifiers resolve against
the importing module's directory. The `{ default: ... }` wrapper shape
matches what real ESM dynamic-import returns, so consumer code that
does `(await import('./mod')).default` works against both ESM-native
runtimes and our CJS-backed implementation.

### Cost

Both substitutions only run when the Babel-on-parse-failure path is
already invoked (i.e., the source had a syntax error the SM45 parser
rejected). String-literal / comment stripping happens before the
need-check, so `'import(' inside a string` doesn't trigger a pointless
rewrite. Scripts that don't use ESM-only constructs pay zero overhead.

### Limitations

- `import()` with a specifier expression containing nested parens
  or commas isn't matched by the regex (e.g.,
  `import(\`./pkg/${name}-${version}.js\`)` works; `import((a, b))`
  doesn't).
- Static `import x from './y'` continues to be lowered by Babel as
  ESM -> CJS as before.
- CJS modules can't synchronously export a value computed via
  top-level await (this is a CJS limitation, not specific to us).
