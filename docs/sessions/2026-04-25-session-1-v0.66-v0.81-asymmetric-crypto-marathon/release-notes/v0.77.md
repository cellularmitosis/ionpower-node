## What's new

### Top-level `await` for entry-point scripts

Closes one of the three "Missing" CommonJS items in the README. The
bootstrap now pre-detects top-level await in source files and wraps
them in an `async function` IIFE before handing them to Babel:

```js
// snapshot.js
var fs = require('fs');
var data = await fetch('https://api.example.com/data').then(r => r.json());
fs.writeFileSync('snapshot.json', JSON.stringify(data));
console.log('saved', Object.keys(data).length, 'keys');
```

```bash
$ ./node snapshot.js
saved 42 keys
```

The pre-detection is a brace-depth-tracking scanner that strips
comments + string literals, then looks for `await` tokens at the
top level (depth 0, outside any `async function` body). It
recognises both `async function` declarations and `async ... =>`
arrow forms. The wrap is harmless if applied to code that doesn't
need it; we only invoke it when the parser has already rejected the
source, so non-TLA scripts pay no extra cost.

### Limitations

- **CJS modules** can't synchronously export a top-level-await
  result. The wrapper kicks off async work that finishes after
  `require()` has already returned. This is a property of CJS, not
  specific to ionpower-node — real Node only supports TLA in ESM.
- The brace scanner has known imprecisions on async arrow bodies
  that don't use braces (`const f = async () => await x();`).
  False-negatives are possible there.
