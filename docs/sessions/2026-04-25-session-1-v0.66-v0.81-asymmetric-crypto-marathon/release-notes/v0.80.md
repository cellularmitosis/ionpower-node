## What's new

### Real `process.stdin.setRawMode()`

Up to v0.79, `process.stdin.setRawMode(true)` was a no-op stub that
only flipped an `isRaw` flag. CLI prompt libraries (inquirer, prompts,
blessed, ink) silently broke — their per-keystroke read loops kept
seeing line-buffered, ICANON-mode TTY input.

v0.80 ships a `tcsetattr`-backed implementation:

```js
process.stdin.setRawMode(true);
// terminal is now in raw mode:
//   - no line buffering
//   - no echo
//   - no signal-char generation (^C / ^Z bypassed)
//   - 8-bit clean
//   - per-byte reads (VMIN=1, VTIME=0)

process.stdin.setRawMode(false);
// terminal restored to exactly what the user had before the first
// setRawMode(true) call -- saved at first call via tcgetattr.
```

Backed by a new `process._setRawMode(fd, raw)` native that uses
`tcgetattr` / `tcsetattr` from `<termios.h>`. No-op (returns false)
when `fd` isn't a TTY, matching Node's behaviour for piped stdin.

### `TIOCGWINSZ`-backed terminal sizing

`process.stdout.columns` / `.rows` now report the real terminal size
queried via `ioctl(TIOCGWINSZ)` at install time, instead of the
hardcoded 80×24 placeholder. Falls back to 80×24 if the ioctl fails
or the controlling terminal hasn't been sized yet.

### Why this matters

The `tty` row in the README goes from "Stub" to "Working". CLI tools
that gate behaviour on real raw-mode (prompt UIs, single-keypress
menus, line editors) now actually work — previously they'd hang
waiting for line-buffered input that never came in raw mode.

### Smoke

`test/raw_mode_smoke.js` exercises the surface (native bindings
exposed, no-op behaviour on non-TTY stdin, flag toggling, columns/rows
when run interactively). The smoke runner pipes stdin, so we can't
exercise raw-mode reads end-to-end in CI, but the surface is verified.
