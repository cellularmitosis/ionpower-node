# ionpower-node v1.2

**Headline: three small wave-3 unblockers — `pg`, `redis@4`, `figlet`
all load now.**

Pass-16's 28-package wave-3 survey ended at 57 % OK and flagged three
small-fix candidates. v1.2 lands those fixes and runs through the
triad cleanly. The figlet fix turned out load-bearing for an
unrelated class of bug: SM45 does not per-iteration-bind `let` /
`const` in any loop form, so any user package whose closures capture
a `for (let)` / `for (const)` iteration variable was silently wrong.
v1.2 routes those files through babel pre-emptively, which lowers
block-scoping to per-iteration `var` + IIFE and restores correct
capture.

## 1. `Buffer.prototype.write(string[, offset[, length]][, encoding])`
([`src/node_compat/buffer.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.2/src/node_compat/buffer.cpp))

`pg-protocol`'s [`buffer-writer.js:44`](https://github.com/brianc/node-postgres/blob/master/packages/pg-protocol/src/buffer-writer.ts)
calls `this.buffer.write(string, offset)`. Pre-v1.2 we threw
`this.buffer.write is not a function` — the kPatch installed
`writeUInt8` / `writeUInt32BE` etc. on `Uint8Array.prototype` but not
the string-write entry point.

The Node signature is unusual (the encoding can sit in the offset OR
length slot if a string lands there). We match it via JS-side argument
shuffling and route the bytes through `Buffer.from(string, encoding)`
for the encoding work, then copy.

Smoke at [`test/buffer_write_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.2/test/buffer_write_smoke.js)
covers all 7 call shapes (utf8 default, encoding-as-2nd-arg,
offset-only, offset+encoding, offset+length+encoding, length cap,
hex, base64).

**Unblocks**: `pg` (PostgreSQL driver) and anything else using
pg-protocol or hand-rolled binary serializers.

## 2. `require('.')` and `require('..')`
([`src/node_compat/require.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.2/src/node_compat/require.cpp))

`redis@4`'s [`@redis/client/dist/lib/cluster/multi-command.js:36`](https://github.com/redis/node-redis/tree/master/packages/client)
calls `require('.')` to mean "this directory's `index.js`". Pre-v1.2
`ResolveModule` gated relative resolution on `./` / `../` only, so
bare `.` and `..` fell through to the bare-specifier `node_modules`
walk and returned MODULE_NOT_FOUND.

Real Node treats `'.'` as `'./'` and `'..'` as `'../'`, both running
through LOAD_AS_DIRECTORY (package.json main, then index.js, then
index.json). v1.2 widens the relative-specifier gate to accept the
two-character bare forms; the downstream `TryModuleExtensions` +
`CanonicalizePath` already handled the rest.

Smoke at [`test/require_dot_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.2/test/require_dot_smoke.js)
sets up a 3-deep dir tree and verifies `require('.')`, `require('..')`,
`require('./')`, and `require.resolve('.')` all hit the expected
`index.js`.

**Unblocks**: `redis@4`, anything that bare-dot-requires its own
directory.

## 3. Pre-emptive babel for `for (let ...)` / `for (const ...)` files
([`src/node_compat/require.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v1.2/src/node_compat/require.cpp))

This started as a figlet fix and turned out load-bearing for any
package that closes over a block-scoped loop variable.

**The bug.** SM45 does not per-iteration-bind `let` or `const` in
any loop form. Verified on v1.1 against the live binary:

    for (const k in obj) arr.push(() => k);    // [c,c,c]  (should be [a,b,c])
    for (let v of [1,2,3]) arr.push(() => v);  // [3,3,3]
    for (let i=0; i<3; i++) arr.push(() => i); // [3,3,3]

In real Node + ES2015+, each iteration creates a fresh binding so
closures capture the right value. SM45 leaks the post-loop value
to every closure. This is a fundamental gap in the engine, not
something we can patch trivially.

**Figlet's trip.** `figlet/dist/node-figlet.cjs` builds a CJS-to-ESM
namespace via:

    for (const k in e) {
      Object.defineProperty(n, k, d.get ? d : {
        enumerable: true, get: () => e[k]   // arrow captures k
      });
    }

Every getter ended up returning `e[lastKey]`, so
`path__namespace.dirname` returned `path.win32` (the last own key
of `require('path')`) instead of `path.dirname` — and the next
call threw "not a function." Pass-16's diagnosis suggested
"path methods aren't enumerable"; that was wrong. The path module
exposes its keys via JS object literal (already enumerable);
`Object.keys(require('path'))` had returned all 15 keys on v1.1.

**Fix.** Babel preset-env at `targets: { ie: '11' }` lowers
block-scoping to per-iteration `var` + IIFE. We verified the
lowered output produces `[a, b, c]` for the same input. v1.2 extends
the babel pipeline (originally only triggered on parse failure) to
**preempt on a cheap source scan**: if a required file's source
contains the substrings `for (let ` / `for(let ` / `for (const ` /
`for(const `, we route it through `__try_babel_transpile__` before
the first evaluate. The disk cache at `~/.ionpower-cache/babel-v1/`
amortizes the cost (per file + mtime); cold-cache hits pay a
babel pass, warm hits don't.

This is a heuristic: over-trigger is strictly more correct but
slightly slower on cold cache; under-trigger is silently wrong
(the figlet trap). We over-trigger by design — files that use
`for (let)` / `for (const)` without closure capture pay an
unnecessary babel pass on first run, but the runtime semantics
are unchanged. Opt-out: `IONPOWER_NO_BABEL=1`.

Smoke at [`test/for_loop_block_scope_smoke.js`](https://github.com/cellularmitosis/ionpower-node/blob/v1.2/test/for_loop_block_scope_smoke.js)
writes three helper files (for-in const / for-of let / `for(;;)` let)
under `/tmp`, requires them, and asserts each captured-closure array
is per-iteration-correct.

**Unblocks**: `figlet`, and any other package whose closures depend
on per-iteration binding (likely many more — wave-4 will tell).

## Verification

Triad-built on G3 (ibookg37), G4 (emac), G5 (pmacg5). Full smoke
sweep — 31 core + 495 libs — passes on every host. Three new core
smokes (`buffer_write`, `require_dot`, `for_loop_block_scope`) make
the totals **34 core + 495 libs = 529 PASS / 0 FAIL per host**.

No regressions vs v1.1. Build wall-clock unchanged.

## What's unchanged

- All v1.1 surface (MODULE_NOT_FOUND code, require.main /
  require.extensions / require.resolve.paths / module.id /
  module.filename, the six lumo asks). Same binary contract.
- SpiderMonkey 45 still lives at `/opt/mozjs-45-ionpower-{g3,g4,g5}/`
  (from v0.87) — unchanged. No mozjs rebuild needed to upgrade
  ionpower-node from v1.0/v1.1 to v1.2.

## Install

```bash
sudo mkdir -p /opt && sudo chmod ugo+rwx /opt && cd /opt
# If not already present from v0.87+:
curl http://leopard.sh/misc/beta/mozjs-45-ionpower-g3.tar.gz | gunzip | tar x
# v1.2 runtime:
curl -L -O https://github.com/cellularmitosis/ionpower-node/releases/download/v1.2/ionpower-node-1.2-g3-ppc.tar.gz
sudo tar xzpf ionpower-node-1.2-g3-ppc.tar.gz -C /opt/
/opt/ionpower-node-1.2/bin/node test/hello.js
```

Replace `g3` with `g4` (G4 7450, 7447) or `g5` (G5 970) as appropriate.
