## Summary

Passes 5–7 each surfaced one or two latent bugs in the handwoven
`_Stream` / `_Readable` / `_Writable` / `_Transform` /
`_IncomingMessage` chain in
[`src/node_compat/globals.cpp`](https://github.com/cellularmitosis/ionpower-node/blob/v0.94/src/node_compat/globals.cpp).
The pass-7 handoff suggested attacking the class rather than reacting
one bug at a time: pull the official Node 10.24.1 stream conformance
tests, wire them in, fix what breaks.

This pass landed 10 distinct fixes in `globals.cpp`, all gated by a
real Node test:

## What's new (pass 8)

### `_Stream.prototype.pipe` — 'pipe' / 'unpipe' events + auto-cleanup

- `pipe(dest)` now emits `'pipe'` on dest at hookup, and `'unpipe'` on
  dest when the pipe is torn down. Reordered so 'pipe' fires BEFORE
  the 'data' listener is attached (since attaching 'data' auto-resumes
  and can synchronously cascade to 'end' + auto-unpipe).
- `unpipe(dest)` is implemented (was missing). Removes only the
  listeners installed by the matching `pipe()` call. `unpipe()` with
  no arg detaches all pipes.
- On src `'end'`, the pipe auto-tears down via `src.unpipe(dest)` —
  matches Node's `Readable.prototype.pipe`.
- Pipe's `onerror` follows Node's legacy `Stream.prototype.pipe` model:
  detach this pipe's listeners, then re-emit on dest *only if* src has
  no other 'error' listener. Avoids the prior bug where every pipe
  re-emitted unconditionally and double-fired downstream listeners
  (`test-stream-pipe-without-listenerCount`).
- `_readableState.pipes` / `pipesCount` are tracked, mirroring Node's
  `null/dest/[dest...]` shape.

### `_Readable` — paused-mode `'readable'`, `_maybeReadMore`, end-emission

- `on('readable')` now triggers a `_read` (via `nextTick`) if the
  buffer is empty, or schedules a `'readable'` emit if data is already
  buffered. Aligns with how Node tells the source "consumer wants
  data" in paused mode.
- `push(chunk)` debounces `'readable'` emits via `nextTick` so multiple
  synchronous pushes coalesce into one notification. Without this,
  `push()` inside the `_read` triggered from inside a 'readable'
  listener re-entered the listener and busy-looped.
- `_maybeReadMore`: on `nextTick` after a push, eagerly call `_read`
  while the buffer is below HWM and the stream isn't
  flowing/ended/reading. Mirrors Node v10's
  `lib/_stream_readable.js`. Fires in BOTH flowing and paused mode —
  it's what keeps a sync-source pipe flowing past the first chunk.
- `push('')` / empty chunk in non-objectMode: doesn't add to buffer
  but DOES acknowledge `_read` and trigger another fetch. Matches
  Node's `readableAddChunk` and `test-stream-readable-event` subtest 4.
- `state.reading` is honest now: `push()` clears it on real data
  arrival; `read()` and the `on('readable')` hook no longer reset it
  after `_read` returns. That gate prevents `_maybeReadMore` from
  over-firing `_read` between consumer demand windows.
- End-emission: `endEmitted` is set to true ONLY when 'end' is
  actually delivered to a listener. If buffer drained + ended + no
  listener, `_endPending` is marked; the `on('end')` hook picks it up
  and schedules a `setImmediate(emit('end'))`. Replaces the pass-7
  setImmediate fallback that fired into the void during a paused
  window.
- `read(n)`: refills via `_read` when below HWM and returns the buffer
  contents in one chunk (Buffer.concat for buffers, String concat for
  strings, first item for objectMode). When `n > highWaterMark`,
  bumps HWM to the next power of 2 ≥ n.
- `readableHighWaterMark` / `readableLength` / `readableBuffer`
  getters added.
- `_readableState.emittedReadable`, `resumeScheduled`, `encoding`
  fields added to the initial state.

### `_Writable` / `_Readable` / `_Duplex` / `_Transform` callable without `new`

Each constructor self-corrects via
`if (!(this instanceof _Stream)) return new _X(opts);`. Several Node
tests (`test-stream-pipe-manual-resume`) call
`stream.Readable({...})` without `new`, which Node supports. The
instance-of check is against `_Stream` (the common base) so that
`_Writable.call(this)` from inside `_Duplex` / `_Transform`
constructors still routes through correctly.

### EventEmitter — `'error'` throw + empty-array cleanup

- `emit('error', err)` with no listener now throws (per Node spec) —
  non-Error arguments are wrapped in a generic Error with the original
  payload on `.context`. pass-7 and earlier silently swallowed
  unhandled 'error' events; real Node streams rely on the throw
  semantics (`test-stream-pipe-error-handling` block 2 and block 3
  both depend on it).
- `removeListener` deletes the event key from `_events` when the
  listener array empties. Some libs + tests check
  `emitter._events.foo === undefined`.

### Test infrastructure

- New dir [`test/node10-streams/`](https://github.com/cellularmitosis/ionpower-node/tree/v0.94/test/node10-streams).
- [`_common.js`](https://github.com/cellularmitosis/ionpower-node/blob/v0.94/test/node10-streams/_common.js) —
  minimal shim of upstream `test/common`'s surface

## What's still pending

5 vendored tests don't pass yet — they're in
[`test/node10-streams/`](https://github.com/cellularmitosis/ionpower-node/tree/v0.94/test/node10-streams)
but **not** wired into `scripts/test-list-more.txt`:

- `test-stream-decoder-objectmode` — requires `utf16le` encoding
  decoder on Readable (we don't apply encoding option).
- `test-stream-pipe-cleanup` — counts `'close'` + cleanup listeners
  that the legacy `Stream.prototype.pipe` installs; our pipe only
  installs 'end' + 'error' + 'data'.
- `test-stream-push-order` — depends on `emitReadable` internal timing.
- `test-stream-readable-emittedReadable` — dynamic
  `emittedReadable` flag semantics (set true at emit, reset to
  false during `read()`).
- `test-stream-readable-resumeScheduled` — dynamic
  `resumeScheduled` flag.

The initial values for `emittedReadable` and `resumeScheduled` ARE
correct now (initialized to `false` in `_readableState`); the
dynamic transitions are deferred.

## Compatibility

Same SpiderMonkey, same OpenSSL, same JIT. Existing v0.93 scripts run
unchanged. The 10 stream-engine changes are designed to be strictly
Node-compatible (each one is gated by an upstream test); the
EventEmitter `'error'` throw change is the biggest behavior shift —
v0.93 silently swallowed unhandled `'error'` events; v0.94 throws
(matching Node). Code that previously emitted errors into the void
will now crash; that's correct behavior, but worth knowing.
