# ionpower-node 0.9 — real event loop

This release replaces the sync-drain-on-exit model with a proper
`select()`-based event loop, and lands async `child_process.spawn`
/ `exec` / `execFile` on top of it.

Library count: **504** (unchanged — this release is about the
runtime feature, not more libraries). Assertions: **1205 → 1220**.
Triad-validated on G3 / G4 / G5.

## What's new

### Real event loop

`src/node_compat/event_loop.cpp` (~310 lines). Shape:

```
while (pending timers || watchers || children):
    timeout = next_timer_fireAt - now
    select(readFds, writeFds, timeout)
    if SIGCHLD: reap via waitpid(WNOHANG) + fire JS callbacks
    for each ready fd: fire watcher callback
    fire due timers
```

Exposed to JS via `ioWatch(fd, events, cb)` / `ioUnwatch(id)` /
`childRegister(pid, cb)` / `childUnregister(pid)`. Callbacks are
stored in JS-side tables keyed by id/pid so the C++ side never
has to root a `JSObject*`.

### Wallclock timers

`setTimeout(fn, 100)` now actually waits ~100 ms. Previously the
drain loop fired every queued timer synchronously before exit —
ordering was correct but absolute delays collapsed to zero. Now
the loop `select()`s until the next fireAt (or until a signal /
fd event wakes it).

Intervals self-requeue; `setImmediate` fires ahead of any
`setTimeout(fn, >0)`; `clearTimeout` / `clearInterval` still work.

### Async `child_process`

- `spawn(file, args, opts)` returns a `ChildProcess` (EventEmitter)
  with `.pid`, `.stdout` / `.stderr` (Readables), `.stdin` (Writable),
  `.kill`. Emits `'exit'(code, signal)` then `'close'(code, signal)`
  after fd drain.
- `exec(cmd, [opts], cb)` — `sh -c <cmd>`, concats stdout/stderr,
  fires `cb(err, stdout, stderr)` on close.
- `execFile(file, args, [opts], cb)` — same but direct exec.

Implementation: non-blocking fork+exec sets `O_NONBLOCK` on the
three pipe fds; `readFd`/`writeFd` native primitives return
`wouldBlock` flags; the JS Readable/Writable plumbing lives on
`ioWatch`. `SIGCHLD` + `waitpid(WNOHANG)` reaps exited children.

Sync variants (`execSync`, `spawnSync`, `execFileSync`) still
work exactly as in v0.8.

`fork` still throws — it requires an IPC channel which we don't
have.

### Two new smoke tests

- `event_loop_smoke.js` — real-time setTimeout, ordering across
  loop iterations, setImmediate priority, clearTimeout.
- `async_child_process_smoke.js` — spawn/exec/stderr/stdin round-trip.

## Install

Each tarball installs to `/opt/ionpower-node-0.9/`. Depends on a
matching `/opt/mozjs-45-ionpower*` per CPU.

```
tar -C /opt -xzf ionpower-node-0.9-g5-ppc.tar.gz
/opt/ionpower-node-0.9/bin/node script.js
```

## Known limitations

- `child_process.spawn` stdin write buffering doesn't yet back-pressure
  properly; huge writes may silently truncate. Small writes are fine.
- `fs.createReadStream` / `WriteStream` still missing — would need
  separate work for regular-file async (select() always returns
  ready on regular files).
- `net.Socket` / `http.request` not yet wired — but the event loop
  primitive (`ioWatch`) is the missing prerequisite; these can now
  land as pure JS on top of it.
- `process.stdin` still uses the drain-on-first-listener shim from
  v0.8. Could be rewritten on top of `ioWatch(0, READABLE)` now.
